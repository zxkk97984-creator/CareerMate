## 1. 产品目标与范围

### 1.1 首轮用户与价值主张

默认优先人群：有一个大致目标岗位、每周投入 3–8 小时、需要具体学习/实践步骤的大学生或初入职场者。先用 AI 产品经理作为主验证岗位，数据分析/AIGC 作为回归样本；其他岗位仍能进入既有流程。

一句话价值：**把“我想做什么工作”变成“这周完成什么、怎么做、凭什么判断有进步”。**

首页要回答三个问题：现在做什么；为什么做它；做完后有什么可检查的产出。

### 1.2 本轮必须交付

- 稳定、可发现的 AI 助手入口，历史可恢复、结构化结果可查看。
- 可理解的候选预览与确认；生成计划到正式执行的状态清楚。
- 行动优先的概览；任务、资源、训练、成长证据有可追踪联系。
- 可恢复的加载与错误状态；模块更新不清空当前编辑状态。
- 桌面/平板/手机的核心操作可用，保持现有蓝白品牌与 Kurisu 特色。
- 基线、E2E、评估文档一致，至少一条完整闭环有可复验的证据。

### 1.3 暂不做

社交社区、支付订阅、招聘爬虫、原生 App、复杂运营后台、多模型调度、全量技术栈替换。管理员页首轮只修可用性与门禁，不全面重设计。视觉上不增加新 IP、插画或大型动效工程。

### 1.4 成功指标（待测目标，非现有成绩）

| 指标 | 定义与初始目标 | 采集方法 |
|---|---|---|
| 助手可发现性 | 新用户无讲解 10 秒内找到 AI 入口，5–8 人中至少 80% 成功 | 观察测试，不提前告知右键技巧 |
| 激活 | 完成画像确认 + 接受首个计划 + 将首个任务设为进行中 | 本地业务事件去重后统计；单纯打开页面不算 |
| 完整任务成功率 | 完成预定核心流程的参与者 / 实际尝试者，初始目标 ≥80% | 报告人数和分母，不只报百分比 |
| 确认可理解性 | 能说清“什么字段会改、什么不会改”，初始目标 ≥80% | 候选确认前问一个理解问题 |
| 任务可执行性 | 用户能复述交付物和完成标准，主观评分均值 ≥4/5 | 人工观察与短访谈 |
| 持续使用 | 第 7 天内第二次完成任务/训练的人数；首轮先建立基线 | 不把登录算有效回访，不预设已实现留存率 |
| 可靠性 | P0 流程无未处理异常；确认/重试不重复写入 | 自动化异常场景 + 数据库结果断言 |

## 2. 架构决定

### 2.1 产品入口

- 保留登录后 `/dashboard` 为首页。未完成画像继续使用 `/onboarding`，本轮不引入“无画像游客工作台”。统一现有注册/login/root/WorkspacePage 的路由判定，消除 OPEN_CHAT_ENTRY 与实际守卫不一致。
- 第一阶段保持现有 URL：dashboard/path/simulation/resources/memory/admin。`/chat` 可作为兼容深链接跳 `/dashboard?assistant=open`，由同一个助手面板处理；不要重新挂载一套有独立状态的 ChatHome。
- 所有工作台页的页头有“AI 助手”按钮；Kurisu 也调用同一 openAssistant。角色可收起，失败不影响核心对话。
- 将“记忆权限”改名“成长档案”，首轮沿用 `/memory`；页内三个标签：“待确认建议”“画像与证据”“记忆与隐私”。旧入口仍可达；具体候选支持 `?tab=suggestions&candidate=<id>&kind=<类型>`，类型/ID 必须经服务端授权核验。
- 候选入口同时存在于概览和结果上下文；不强迫用户到隐私清空区域寻找业务确认。

### 2.2 共享状态边界

- 新增一个客户端 AssistantProvider / useAssistantController，放在跨工作台导航保持挂载的层，负责 activeConversation、messages、stream 状态和草稿。角色组件只负责展示/动作，不管理第二套消息数组。
- 保留 MessageItem / ChatMessagePart 真源及 `consumeFrontendSseResponse`。提取 ChatHome 可复用逻辑时逐段迁移并测试，不整体复制。
- 工作台壳负责认证信息、导航和页面级提示；每个视图读取自己的业务 slice。更新接口返回的数据应先更新对应 slice，再后台刷新必要摘要。
- 首轮无需引入外部缓存库；小型带请求取消与 request sequence 的 hook/context 已足够。避免自建通用 query 框架。
- 候选“统一”首先指 UI 读模型。V1 画像、pending CareerPlan、V2 artifact 的写接口不合并成一个未经验证的新万能接口。

### 2.3 计划与学习路线

- CareerPlan 是方向/阶段/任务执行真源，LearningRoute 是已确认的学习安排与资源。先展示两者关系，不重复创建第二套任务状态。
- 复用现有 `src/lib/tbox/plan.ts` 和 `UnifiedPlan`，不再新建第三套 V1/V2 计划转换。
- 第一批任务详情先用已有 `practiceOutputs`、`evaluationMetrics`、estimatedHours 等真实数据；缺值显示“待细化”，不能凭前端随机填入。
- 确需新增单任务交付物/验收标准时，采用明确版本化的 JSON 扩展；同步 parser、DTO、投影、fixture 与测试。只有任务产出需要独立检索/关系时才新增表。
- 任务完成记录不等于能力自动增长。能力变化仍走 evidence/candidate/confirmation。

### 2.4 公共响应约定

保留后端 `{ok,data,meta}` 结构。客户端改为可判别联合，错误保留 HTTP status、code 和 requestId；不要将 HTTP 200 与 body.ok 混用。

```ts
// 目标形状示意，实施时复用现有 metadata 类型。
type ApiResult<T> =
  | { ok: true; data: T; status: number; meta?: ApiMeta }
  | { ok: false; status: number; error: {
      code: string; message: string; requestId?: string;
    }};
```

- 空响应、非法 JSON、网络失败分别归一化；网络失败 status 可用 0，并明确 code。
- AbortError 作为取消分支处理，不显示“服务错误”；不自动重放 POST/候选接受。
- 只对明确 401 触发登录；403 权限提示，404 资源不存在，409 版本冲突，422 补齐信息，429 稍后重试，5xx 保留现场。
- `meta` 不能仅限制为 AiExecutionMeta；普通分页/requestId 和 AI 执行来源是不同字段语义。

## 3. 关键业务规格

### 3.1 助手状态与消息

状态至少包含 closed、loadingHistory、ready、sending、streaming、failed。关闭面板仅隐藏，不默认丢弃当前流或草稿；切换会话时禁止旧流写入新会话，选择“切换时取消当前显示订阅并按会话保存状态”或“流式期间禁用切换”中的简单可靠方案并明确 UI。

一条逻辑发送在超时后重试要复用同一个 clientRequestId；明确开始新的提问才生成新 ID。服务器已保存但响应丢失时，先读取消息状态，避免制造重复用户消息和候选。客户端 Abort 不能伪称服务器业务操作已撤销。

正文用已有 Markdown 渲染，artifact 用既有 parts 渲染，来源/降级状态用实际执行 meta。对话产生候选时显示卡片与“查看建议”，同时刷新候选摘要。历史加载保留 message id、parts、status、executionMeta，不能退化成纯字符串。

历史分页保持当前接口 `data: MessageItem[]`；会话列表是 `{items,nextCursor}`。不要误改成同一响应形状。列表空态、50 条历史截断/加载更早消息均需明确处理。

### 3.2 建议中心的统一读模型

```ts
type SuggestionRef =
  | { kind: 'profile'; id: string }
  | { kind: 'plan'; id: string }
  | { kind: 'memory'; id: string }
  | { kind: 'artifact'; id: string };
// 列表项另附 title/status/createdAt/summary；详情按 kind 判别，禁止 any。
```

列表 count 与列表过滤必须同源：只计可处理的 pending。不同存储源用 kind+id 作为 UI key；同一业务建议如果存在显式 source/parent 关联才去重，不能按标题或创建时间猜测。

候选详情必填展示：建议类型、理由、证据摘要、当前值、新值、影响范围、实际来源、当前状态。版本化候选显示已基于哪个版本生成；无需把技术 ID 暴露为主标题。

按钮：详情加载前禁用“确认更新”；加载失败“重试加载”；提交中禁用本卡操作；成功保持终态并更新概览；409 显示“资料已变化，请重新生成建议”，禁止覆盖提交；404 显示“建议已不存在”；再次打开已处理卡不得先闪出 pending 操作。

现有写接口必须按原协议调用：

- V1 画像：`PATCH /api/profile/candidates`，`{candidateId,action:'accept'|'reject'}`；既有 edit 分支另带 newValue，不能与记忆建议接口混淆。
- V1 记忆建议：`POST /api/memory/:id/decision`，`{action:'accept'|'reject'}`；既有 edit 只编辑提案文本，不应自行当成 accepted。来源为 `/api/memories` 中 status=pending 的记录。
- pending 计划：`POST /api/plans/:id/decision`，`{action:'accept'|'reject'}`；响应 accept 是 `{new:{id,status}}`，reject 是 `{rejected:true,planId}`，客户端不能假设都返回完整 plan。
- V2：`POST /api/agentic-v2/candidates/:id/decision`，`{decision:'accept'|'reject'}`。

### 3.3 首页“下一步”选择规则

依序评估：画像未完整 → 去引导；无 active 计划但有 pending → 审阅计划；无计划 → 生成首个计划；有进行中任务 → 继续该任务；有延期任务 → 查看延期并调整；其他未完成任务 → 推荐按 dueWeek、原始顺序选择第一项；本期全完成 → 查看复盘/下一阶段。

不能从 `dueWeek` 推断真实日历到期日；没有 activatedAt/明确计划起点时只写“第 N 周”。优先级排序保持确定性，不每次刷新随机推荐。

pending 重规划作为额外提示，不替换仍在执行的任务。业务 mutation 成功之前不改正式分数。

### 3.4 分数与 AI 来源

- 当前 calculateMatch 的加权值命名“成长参考分”，展示 `50 / 100`，不写“50% 胜任概率”。说明“基于已记录能力和岗位权重，供学习安排参考”。
- 无岗位模板/必要能力记录时显示“信息不足”，不能把 null 兜底成 0；0 只有真实记录为 0 才显示。
- 推荐补弱优先级可按 `weight * (100 - score)` 排序，前提是确认当前分值量纲为 0–100、权重有效且归一化；缺少数据的维度单独列出“待评估”，不要参与猜测排名。
- 如果以后要叫“岗位匹配度”，必须另定义岗位目标阈值、评分模型与验证样本；本轮不擅自改算法制造更高分。
- UI 标签：实际 mock = “演示数据”；manual = “人工样例”；api 成功 = “AI 生成”；降级 = “本次使用演示数据/人工样例”。开发字段放折叠诊断，不使用 `TBOX_MODE=...` 作为唯一面向用户的表达。
- 配置为 api 但尚未执行，只显示“AI 服务待使用”，不能暗示本次结果来自实时调用。HTTP 通路成功不等于输出质量已验证。

### 4.2 布局断点

- ≥1280px：240px 左侧导航 + 内容区；概览主区域 8/4 比例，左侧任务、右侧参考分/待确认摘要。总宽度受 1120px 上限控制。
- 1024–1279px：220px 导航；优先保证主区 ≥640px；不挤出 4 列窄卡。
- 768–1023px：导航改抽屉，顶部固定 56px 工具栏；主区最多两列。
- ≤767px：单列；顶部 56px 工具栏，下方只有一个业务 h1。第一屏必须能看到下一步主按钮。指标压为一行 2–3 项，雷达在任务之后。
- 验证宽度：360、390、768、1024、1440；高度至少覆盖 640/844/900。长中文标题、浏览器 200% 缩放和安全区要单独检查。
- 顶部工具栏包含菜单与助手，不能让悬浮角色成为唯一入口。手机助手使用全屏 sheet：`100dvh` + safe-area，输入框贴近键盘上沿且消息区独立滚动。
- 遮罩/抽屉只锁定真实滚动容器；关闭恢复滚动位置。不能依靠全局 overflow hidden 掩盖布局溢出。

### 4.3 各页面的目标结构

**成长概览**

1. 页头：“成长概览”；次行显示目标岗位与投入时间；右侧“AI 助手”。
2. 下一步主区域：状态短标签 → 任务标题 → 推荐原因 → 预计投入/交付物 → 一个主按钮“继续任务/审阅计划/生成计划”。
3. 紧凑摘要：“本期已完成 1/3”“待确认建议 2”“本周已训练 1 次”；没有真实数据时不渲染伪计数。
4. 当前任务列表：默认 3 项，更多去职业路径。每行有任务名、状态、相对周次、明确可点击入口。
5. 参考分与能力图：次级区域，显示缺失信息与“查看依据”。
6. 最近成长记录：事件对应中文名称和真实时间，点击跳相关任务/证据；无可关联对象时保持纯文本。

**AI 助手**

- 桌面右侧面板宽 420px，窄桌面不硬挤业务内容，可覆盖；提供“展开阅读”到宽 760px 的模式，复用同一 controller。
- 顶部：标题、当前会话、新对话、历史、关闭；每个 icon button 有 aria-label。新对话不删除旧会话。
- 初次空态：“可以问我职业方向、学习安排，或一起复盘当前任务。”只给 3 个与当前页面相关建议。
- 中部：消息、来源、候选卡；长代码/链接内部折行或局部滚动，不撑宽页面。
- 底部：多行 textarea；Enter 发送、Shift+Enter 换行，中文输入法 composing 时不发送。输入有可见 label 或可访问名。
- 发送失败保留草稿/消息并显示重试；流中显示“正在回复”，不能从开始到结束始终写“正在思考”。
- 角色支持收起/恢复；桌面默认避开主操作区，手机默认紧凑按钮。角色加载超时提供静态替代，面板仍可使用。

**职业路径**

- 页头：“职业路径”，说明当前目标与正式版本；重规划为次要按钮。
- 若有候选，页头下显示单行“新计划待确认”与“查看变化”，不把候选的时间线替换当前计划。
- 页内分组：“当前任务”“阶段路线”“学习安排”。首屏显示当前任务，不直接展开 36 个月全部信息。
- 任务详情桌面右侧抽屉、手机全屏：目标、步骤、时间、交付物、完成标准、资源、状态操作。缺信息显示“让 AI 细化”，不能把未知值填成确定要求。
- 版本对比：当前 vN / 建议 vN+1；方向变化、增删任务、时间投入和风险变化；明确“确认后执行，旧版保留”。
- 学习路线展示关联计划版本；关联的是已归档计划时明确提示需复盘，不自动迁移。

**成长档案（沿用 /memory）**

- 默认标签“待确认建议”，按类型筛选；空态说明“AI 提出更新时，会先在这里等你确认”。
- 画像与证据标签展示基础信息、能力依据，支持进入现有修改/候选流程，不直接编辑能力分数。
- 记忆与隐私标签放记忆开关、列表、导出；清空成长数据放最下方独立危险区域，不与候选确认挨在一起。
- 记忆关闭时明确是“不再用于后续记忆功能”还是“停止保存/停止召回”，文案必须与后端实际行为一致。
- 删除/清空保留已有二次确认；异步失败保留输入，不自动关闭；确认弹窗需焦点圈定和关闭后回焦。

**模拟训练**

- 无进行中会话：场景列表 + 一张选中场景说明 + “开始训练”。
- 有进行中会话：当前训练/轮数和“继续回答”最优先；场景说明默认折叠，不显示大片被禁用卡片。
- 评分中：保留完整记录、禁止重复完成，不卸载页面；失败能重试当前评分。
- 完成：分数或“未评分” → 证据摘录 → 一条主要改进 → 查看候选/返回任务；不得把候选建议写成已确认能力提升。
- 实际读取本地场景的按钮写“刷新推荐场景”，不写 AI 生成；来源标签和实际行为一致。

**资源中心**

- 岗位、能力、类型合并紧凑筛选区；搜索 label：“搜索学习资源”，底层供应商写在来源说明，不占主按钮。
- 卡片：标题、为什么推荐、类型/预计时长/来源、明确动作。外链用真实 `<a>`；没有 URL 时动作“查看实践说明”或纯说明，不伪装可跳转卡片。
- 由任务进入时保留 taskId/planId 上下文，显示“为当前任务查找资源”和返回任务。任意 query 参数不可信，服务端按用户核验需要读取的实体。
- 首轮只读关联已有资源；“收藏”“加入计划”没有持久化实现前不要显示空按钮。

### 4.4 必须覆盖的状态和文案

| 场景 | UI 规则 | 推荐文案 |
|---|---|---|
| 首次加载 | 外壳与对应内容骨架，避免全页白屏 | “正在读取你的成长记录” |
| 后台刷新 | 内容保留，局部小状态 | “正在更新” |
| 模块失败 | 失败模块就地重试，其他模块继续 | “计划暂时未能加载，重试后继续” |
| 新计划生成 | 显示候选入口，不改当前任务 | “新计划已准备好，确认后开始执行” |
| 保存任务失败 | 还原已显示的乐观状态或不提前改状态 | “保存失败，任务状态未改变” |
| 候选版本冲突 | 禁止强制提交，保留可读预览 | “资料已更新，这条建议需要重新生成” |
| 历史会话为空 | 显示真实空态，允许输入 | “这个会话还没有消息” |
| 无评分 | 不渲染 0 分圆环 | “本次训练未产生评分” |
| 无任务 | 一个明确主动作 | “先生成一个适合本周投入的计划” |
| AI 降级 | 结果旁持续标记，折叠详细原因 | “本次使用演示数据” |

所有提交结果同时有可见反馈和 aria-live；禁止只调用 setNotice 写入 sr-only，让视觉用户无从知道结果。

### 4.5 无障碍与交互验收

- 键盘能打开导航/助手/候选/任务详情，Escape 关闭，焦点进入浮层并在关闭后回触发点。
- 真正模态才用 aria-modal + focus trap；桌面非模态侧面板不能错误限制用户访问主区。
- aria-controls 对应真实 id；当前 ProductSidebar 只有 data-testid 时需补 id，不能把它当 id 使用。
- 正文、AI 输出、任务步骤可选择复制；拖拽把手才使用 user-select:none。
- 不仅靠颜色表达状态。正文/交互文本对比度目标 4.5:1，大号文字 3:1；实际测量并保存结果，不凭截图宣称达标。
- reduced-motion 覆盖 Recharts、GSAP 和 Live2D 的实际运动；CSS 禁止动画不等于 iframe/JS 动画已停止。

## 8. 风险与回退

| 风险 | 控制与回退 |
|---|---|
| 工作区并行改动 | 每任务前检查 diff；有重叠先明确 ownership；禁止覆盖用户改动 |
