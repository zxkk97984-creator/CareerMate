# T23b 公开部署的限流位置、配置、429 行为和适用范围

日期：2026-09-06 · 执行：agent · 对应提交：`ff6b320`

## 目标（plan T23b）

- 核对你已有部署层限制，限流采用部署/网关层而非进程内。
- 覆盖登录、注册、昂贵 AI 入口；单实例可采用现有基础设施。
- 不能把进程内 Map 宣称多实例有效。
- 限流部署位置、阈值、429 恢复文案与测试明确，多实例适用边界已记录。
- 不把原始密码/令牌/聊天正文写入诊断日志。

## 决策与说明

**限流放在反向代理/网关层，不在应用进程内。**

当前仓库不内置进程内限流器。原因：进程内 Map/固定窗口在**多实例**下各自计数、无法跨实例共享；若宣称其多实例有效，会给出错误的部署预期。当前部署形态为单实例自托管 + 反向代理（见 DEPLOY.md §1），限流由代理承担，多实例时各实例天然共享同一代理的限流窗口，故多实例边界也由该层决定。这是 plan 明确要求“不能拿进程内 Map 冒充多实例有效”的正面处理：**不做假限流器，而是把位置、阈值、边界写清楚。**

## 变更

### `src/agentic-v2/deploy/DEPLOY.md`（新增 §8 公开部署的限流）
- **位置**：反向代理/网关层。
- **阈值建议表**：`/api/auth/login` 每 IP 5/分、`/api/auth/register` 每 IP 3/分、聊天 stream 每用户 30/分、`/api/plans/generate` 每用户 3/时、`/api/simulations/:id/complete` 每用户 10/时。
- **429 行为**：`HTTP 429` + `Retry-After`；响应体 `{"ok":false,"error":{"code":"RATE_LIMITED",...}}`；客户端（`client-api.ts`）已识别 `RATE_LIMITED` 并展示内置恢复文案 `操作过于频繁，请稍后重试`。
- **应用层已做**（T23a `parseBodyJson`）：请求体 16KB 上限、空体/坏体 400、认证字符串长度上限。
- **多实例适用边界**：代理限流覆盖多实例；若无代理多实例直连，需选共享存储限流（如 Redis），本仓库不内置、也不宣称进程内方案多实例有效。

### 429/恢复文案测试
`src/lib/client-api.test.ts` 已有 `[429, "RATE_LIMITED"]` 映射用例；恢复文案 `操作过于频繁，请稍后重试` 已内置为 429 默认消息。

## 剩余风险 / 待验证

- 实际限流需反向代理（如 Nginx `limit_req` / Traefik / 云网关）实施，仓库无法脱离部署环境实测；DEPLOY.md 提供阈值与 429 契约，部署团队按此配置。
- 不提供 Redis/共享存储限流实现（符合“单实例可用现有基础设施，不假装多实例”）。
- 跨用户读写回归：未改动认证/会话/隔离机制，既有 auth/session/security 测试覆盖。
