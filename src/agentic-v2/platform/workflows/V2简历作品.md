# V2简历作品

`taskType` 固定为 `resume_review`。开始节点三个文本参数必须绑定：`request`、`task_context_json`、`evidence_bundle_json`。

## R1 兼容边界

当前后端只把 `resume_review` 的 `abilityEvidence` 作为可确认候选消费，尚不接受完整审阅报告 `data`。完整改写建议由主 Agent 在正文中给出；本工作流只提取可追溯的个人能力证据。

## 输出

```json
{
  "schemaVersion": "1.0",
  "taskType": "resume_review",
  "status": "pending_confirmation",
  "summary": "从简历项目中提取数据分析能力证据",
  "data": {
    "abilityEvidence": [

  "evidence": ["简历原文中的项目段落"],
  "sources": [],
  "assumptions": [],
  "warnings": ["未补充原文不存在的量化结果"],
  "requiresUserConfirmation": true,

  "nextActions": ["确认后写入能力证据"]
}
```

## 规则

- 只从用户真实材料中提取事实，不创造公司、项目、数字、奖项或成果。
- 每条证据必须有 `abilityKey`、`summary`、`sourceType`、`sourceRef`、`confidence`。
- 没有可验证个人表现时返回 `needs_input`，不要为了输出候选而补造能力。
- 没有用户保存意图时，主 Agent 可以只返回正文改写建议，不强制生成候选。
- 完整简历报告结构属于后续 R2 协议，当前后端会拒绝把它放进 `data`。

## 代码节点

代码节点由 `npm run tbox:bundle` 从当前后端契约生成，使用导出目录中本工作流的 `code-node.js` 全文。不得从历史文档复制旧代码。代码输入绑定见同目录 `绑定步骤.md`。

结束节点只返回 `artifact`。
