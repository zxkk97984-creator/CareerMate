# V2场景生成

## 用途

把推荐场景、岗位样本或用户自定义描述转成一份可预览、可编辑、可保存的固定场景快照。它只生成场景，不创建训练会话、不评分、不修改画像。

开始节点三个文本参数必须绑定：`request`、`task_context_json`、`evidence_bundle_json`。缺任一参数时不要运行；由主 Agent 重新绑定后再调用。

## 输入

开始节点三个文本参数：`request`、`task_context_json`、`evidence_bundle_json`。

`task_context_json` 至少包含：

```json
{
  "schemaVersion": "1.0",
  "taskType": "simulation_scenario",
  "currentTime": "2026-09-09T08:00:00+08:00",
  "timezone": "Asia/Shanghai",
  "profileVersion": 3,
  "activePlanId": null,
  "basePlanVersion": null,
  "activeLearningRouteKnown": false,
  "baseRouteVersion": null,
  "weeklyBudgetHours": null,
  "requestedPeriod": null,
  "simulationState": null,
  "expectedRound": null,
  "purpose": "interactive_artifact",
  "source": "simulation",
  "sourceType": "custom",
  "sourceRef": null
}
```

`evidence_bundle_json` 可包含目标职业、岗位 JD、历史训练摘要和用户自定义描述。没有岗位 JD 时不要编造岗位要求。

## 输出

只输出一个 JSON 对象：

```json
{
  "schemaVersion": "1.0",
  "taskType": "simulation_scenario",
  "status": "success",
  "summary": "生成自定义跨部门沟通场景",
  "data": {
    "sourceType": "custom",
    "sourceRef": null,
    "scenarioSnapshot": {
      "key": "custom",
      "title": "项目延期沟通",
      "difficulty": "L2",
      "durationMinutes": 8,
      "skills": ["communication", "projectPractice"],
      "role": "项目协调人",
      "counterpart": "跨部门负责人",
      "objective": "在项目延期时同步风险、依赖和下一步，并争取对方确认",
      "brief": "项目关键依赖未按期交付，你需要在没有实时会议的情况下推动对方给出新时间点。",
      "openingMessage": "你是项目协调人，对方是跨部门负责人。请先说明你了解到的延期事实和希望对齐的下一步。",
      "prompts": [
        "请补充你判断风险优先级的依据。",
        "如果对方认为不是自己的责任，你会怎么推进？",
        "请给出一个可执行的备选方案。"
      ],
      "scoringDimensions": ["事实清晰", "风险意识", "推进能力", "复盘意识"]
    }
  },
  "evidence": [],
  "sources": [],
  "assumptions": [],
  "warnings": [],
  "requiresUserConfirmation": false,
  "baseVersion": null,
  "nextActions": ["在本地预览页编辑后开始训练"]
}
```

输出必须满足以下机器契约：

1. 顶层 `schemaVersion` 必须是字符串 `"1.0"`，不能省略、改数字或放到 `data` 内。
2. `scenarioSnapshot.prompts` 和 `scenarioSnapshot.scoringDimensions` 必须是字符串数组，不能输出 `{dimension, description, maxScore}` 一类对象数组；`skills` 也必须是字符串数组。
3. `key` 对自定义场景固定为 `custom`；`difficulty` 只能是 `L1`、`L2`、`L3`；`durationMinutes` 必须是整数。
4. 所有字符串值内部优先使用中文引号“”，不要使用未转义的 ASCII 双引号；必须使用 ASCII 双引号时写成 `\"`（一个反斜杠加双引号），例如 `"brief":"对方说\"需要延期\"。"`。
5. 字符串中的换行必须写成 `\n`（一个反斜杠加字母 n），例如 `"brief":"第一行\n第二行"`；字符串内部不能输出真实换行；不得使用尾随逗号、注释或 Markdown 围栏。
6. 输出前自检：整段文本可被 `JSON.parse` 解析，且只包含一个顶层对象。代码节点会再次校验，语法或 schema 不通过时返回 `INVALID_JSON` / `INVALID_ARTIFACT_SCHEMA`，不能把原始文本当成功结果返回。

## 规则

1. 推荐场景使用后端提供的场景快照，不重新发明角色和目标；
2. 岗位样本场景只使用 `evidence_bundle_json` 中已导入的岗位标题、JD 和技能，不新增爬虫或公开招聘服务；
3. 自定义场景只补问必要信息：事件经过、双方角色、训练目标、难度；
4. 生成后允许用户编辑；编辑结果由本地后端保存为开始快照；
5. `scenarioSnapshot.key` 只能是 `custom` 或现有场景键；`sourceType` 只能是 `recommended` / `custom` / `job`；
6. 不输出评分、报告或能力证据；这些由现有职场模拟工作流和完成 API 处理；
7. 只有 sourceType=job 且任务依赖该岗位时才要求岗位 JD；自定义/推荐场景不要求 JD。缺双方角色或训练目标时返回 needs_input，不补造个人经历。
8. 推荐和岗位样本场景优先使用后端/本地已提供的快照；自定义场景必须来自本工作流的固定字段，不引用未提供的个人经历。

## 代码节点

代码节点由 `npm run tbox:bundle` 从当前后端契约生成，使用导出目录中本工作流的 `code-node.js` 全文。不得从历史文档复制旧代码。代码输入绑定见同目录 `绑定步骤.md`。

结束节点只返回 `artifact`，不得额外输出第二份正文。
