# V2成长复盘

`taskType` 固定为 `growth_review`。开始节点三个文本参数必须绑定：`request`、`task_context_json`、`evidence_bundle_json`。

## 输入边界

- 必须读取 `historySnapshot.data.activePlan` 的完整计划、任务状态、进度和已确认证据。
- 历史不足时只说明“未观察到”，不得声称能力上升或下降；未知不等于 0 分。
- `plan` 必须是修正后的**完整** `AiCareerPlanV2`，不是局部 `planPatch`。
- `planPatch.parentPlanId` 指向原活动计划 ID；没有活动计划时返回 `needs_input`。

## 质量门

与 `career_plan` 相同：每个动作必须有对象、描述、投入、产出和验收标准；否则后端返回 `PLAN_QUALITY_REJECTED`。不能把 `planPatch` 当成完整计划通过验收。

## 代码节点

代码节点由 `npm run tbox:bundle` 从当前后端契约生成，使用导出目录中本工作流的 `code-node.js` 全文。不得从历史文档复制旧代码。代码输入绑定见同目录 `绑定步骤.md`。

结束节点只返回 `artifact`。
