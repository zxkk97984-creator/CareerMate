# V2职业规划

`taskType` 固定为 `career_plan`。开始节点三个文本参数必须绑定：`request`、`task_context_json`、`evidence_bundle_json`。

## 输入与版本

- 目标职业、总周期和每周预算不完整时返回 `needs_input`，不要自行补默认值。
- `baseVersion` 取当前活动计划版本；后端明确确认没有活动计划时为 `null`，不得用 `0` 冒充。
- 已有活动计划时，必须基于 `evidence_bundle_json.historySnapshot.data.activePlan` 生成完整新版计划，不能只返回补丁或局部阶段。

## 质量门

后端会对新计划执行质量检查。每个 `phases[].actions` 和 `immediateActions` 必须同时具备：

- 明确动作对象；
- 可执行 `description`；
- `estimatedHours` 或 `cadence`；
- `outputs` 或阶段 `outputs`；
- `acceptanceCriteria` 或阶段 `evaluationCriteria`。

“完成一个知识点”“输出一个产出”这类标题即使 JSON 结构合法，也会被后端拒绝。旧计划仍可只读读取，但不会通过质量门写回。
