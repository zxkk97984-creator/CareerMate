# V2职场模拟

## 固定场景快照

开始训练时，本地后端已经保存（场景生成工作流只生成草案，不负责保存）：

- `scenarioSnapshot`：角色、对话对象、目标、难度、评分维度、开场白；
- `scoringSnapshot`：评分维度、最多轮次、来源；
- `sourceType`：`recommended` / `custom` / `job`；
- `sourceRef`：岗位样本 ID 或空值。

本工作流只消费固定快照。追问和报告不得改变角色、目标、难度或评分维度；缺快照时返回 `error`，不要用默认场景补。

## taskType 与状态

| taskType | 用途 | 正确 status | 本地行为 |
|---|---|---|---|
| `simulation_turn` | 单轮追问 | `success` | 追加到训练会话，不创建候选 |
| `simulation_report` | 训练完成报告 | `success` | 保存报告；由完成 API 根据 `candidateUpdates` 派生待确认能力证据 |
| `simulation_scenario` | 场景生成/预览 | `success` | 只读预览，不直接创建正式训练 |

`simulation_report` 的完整报告使用 `success`；`pending_confirmation` 仅用于“用户明确要求只保存能力证据候选”的兼容分支。报告保存与能力证据确认是两步，不能混为一步。

## simulation_turn 契约

```json
{
  "schemaVersion": "1.0",
  "taskType": "simulation_turn",
  "status": "success",
  "summary": "第 3 轮追问",
  "data": {
    "sessionId": "sim-session-abc123",
    "scenarioKey": "cross_role_communication",
    "round": 3,
    "nextQuestion": "如果对方不接受你的优先级排序，你会如何调整？",
    "isComplete": false
  },
  "evidence": [],
  "sources": [],
  "assumptions": [],
  "warnings": [],
  "requiresUserConfirmation": false,
  "baseVersion": null,
  "nextActions": []
}
```

约束：

- `sessionId`、`scenarioKey` 必须与固定快照一致；
- `round` 使用 `task_context_json.simulationState.expectedRound` 原样返回，不再次加一；
- `nextQuestion` 只能问一个问题，不能重复历史问题；
- `isComplete` 必须为 `false`；
- 最多 6 轮，至少 3 轮有效回答后由后端结束接口触发报告。

## simulation_report 契约

```json
{
  "schemaVersion": "1.0",
  "taskType": "simulation_report",
  "status": "success",
  "summary": "跨岗位沟通训练报告",
  "data": {
    "sessionId": "sim-session-abc123",
    "scenarioKey": "cross_role_communication",
    "score": 78,
    "strengths": ["能先澄清目标，再提出推进顺序"],
    "improvements": ["风险描述缺少可验证的时间点"],
    "evidence": ["第 2 轮回答：先确认双方共同目标，再拆分优先级"],
    "abilityImpact": { "communication": 65, "businessProduct": 60 },
    "candidateUpdates": [
      {
        "field": "abilityScores.communication",
        "newValue": 65,
        "confidence": 0.78,
        "reason": "用户在本场训练中展示了目标澄清和优先级协调",
        "evidenceExcerpt": "先确认双方共同目标，再拆分优先级",
        "impactSummary": "建议补充一条沟通协作能力证据，等待用户确认",
        "requiresConfirmation": true
      }
    ]
  },
  "evidence": [],
  "sources": [],
  "assumptions": ["仅基于本场训练回答，不代表真实工作全部表现"],
  "warnings": [],
  "requiresUserConfirmation": true,
  "baseVersion": null,
  "nextActions": []
}
```

约束：

- `score` 0–100，评分依据必须能在 `evidence` 中找到；
- `evidence` 必须引用本场用户实际回答；没有可用回答时省略该轮，不要编造；
- `abilityImpact` 只使用六维能力键；
- `candidateUpdates` 只描述“建议补充的能力证据”，不表示已经写入画像；
- 降级报告可以保存分数，但不得生成候选；未观察到的能力明确写为未观察。

## 兼容的 pending_confirmation 分支

只有用户明确要求“只保存一条能力证据”时，才输出：

```json
{
  "schemaVersion": "1.0",
  "taskType": "simulation_report",
  "status": "pending_confirmation",
  "summary": "保存本次训练中的沟通证据",
  "data": {
    "abilityEvidence": [{
      "abilityKey": "communication",
      "summary": "在跨岗位沟通训练中主动澄清双方目标",
      "sourceType": "simulation",
      "sourceRef": "sim-session-abc123",
      "confidence": 0.78
    }]
  },
  "evidence": [],
  "sources": [],
  "assumptions": [],
  "warnings": [],
  "requiresUserConfirmation": true,
  "baseVersion": 3,
  "nextActions": []
}
```

普通训练完成报告不能使用这个分支。

## 代码节点校验

代码节点只接收大模型 `raw`，按以下顺序校验：

1. 去掉代码围栏，只解析一个 JSON 对象；
2. `taskType` 必须是 `simulation_turn` / `simulation_report`；
3. 先处理 needs_input/error，直接保留标准终态；simulation_turn 的 success 才要求 requiresUserConfirmation=false、isComplete=false；
4. `simulation_report` 必须按状态区分 `success` 完整报告与 `pending_confirmation` 能力证据；
5. 缺 `sessionId`、场景不匹配、轮次不是整数时返回标准 `error`，不回显原始输入；
6. 不添加 `CAREERMATE_ARTIFACT` 标签，不在结束节点重复输出。

代码节点由 `npm run tbox:bundle` 从当前后端契约生成，使用导出目录中本工作流的 `code-node.js` 全文。不得从历史文档复制旧代码。代码输入绑定见同目录 `绑定步骤.md`。

## 验收

- 3–6 轮：第 1 轮后追问编号不跳 2；重复问题被拒绝；
- 固定快照：开始后修改角色/评分维度不会影响本场；
- 中断恢复：刷新后仍能继续同一会话，不重复开场、不重复计分；
- 报告：每条评分/优势/改进都能追溯到实际回答；
- 候选：报告保存成功但用户未确认时，正式画像不变。

本次 task_context_json.expectedRound 是后端要求返回的轮次，必须原样使用，不再加一。上下文含 simulationState 才能继续；状态缺失不使用其他会话或默认场景。
