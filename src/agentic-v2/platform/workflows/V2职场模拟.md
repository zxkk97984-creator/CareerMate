# V2职场模拟

## 任务类型与状态规则

| taskType | 用途 | 正确 status | 是否创建候选 |
|----------|------|------------|-------------|
| `simulation_turn` | 单轮追问 | `success` | 否 |
| `simulation_report` | 训练结束报告 | `pending_confirmation` | 是（ability_evidence） |

**关键规则**：`simulation_report` 必须使用 `pending_confirmation` 状态创建能力证据候选。`success` + `requiresUserConfirmation=true` 不会进入确认链（ingestion 仅处理 `pending_confirmation`）。

---

## simulation_turn 完整 JSON 契约

每一轮模拟对话中，AI 输出一个 `simulation_turn` artifact。`data` 必须严格符合 `simulationTurnDataSchema`（strict）：

```json
{
  "schemaVersion": "1.0",
  "taskType": "simulation_turn",
  "status": "success",
  "summary": "第3轮追问：请说明如何处理跨部门需求冲突",
  "data": {
    "sessionId": "sim-session-abc123",
    "scenarioKey": "cross_role_communication",
    "round": 3,
    "nextQuestion": "如果产品经理和技术负责人对需求优先级意见不同，你会如何协调？",
    "isComplete": false
  },
  "evidence": [],
  "sources": [],
  "assumptions": [],
  "warnings": [],
  "requiresUserConfirmation": false,
  "baseVersion": null,
  "nextActions": []
}
```

### simulationTurnDataSchema 字段约束

| 字段 | 类型 | 必填 | 约束 |
|------|------|------|------|
| `sessionId` | string | ✅ | 1-160 字符 |
| `scenarioKey` | string | ✅ | 1-160 字符 |
| `round` | number | ✅ | 整数 ≥ 0 |
| `nextQuestion` | string | ✅ | 1-2000 字符 |
| `isComplete` | false | ✅ | 必须为 `false`（字面量） |

**注意**：`isComplete` 必须是 `false` 字面量（不是 `true`，不是省略）。训练未完成时 AI 不得设置 `isComplete: true`。训练结束时改用 `simulation_report`。

## simulation_report 完整 JSON 契约

训练完成时，AI 输出一个 `simulation_report` artifact。`data` 必须严格符合 `abilityEvidenceDataSchema`（strict）：

```json
{
  "schemaVersion": "1.0",
  "id": "sim-report-abc123",
  "taskType": "simulation_report",
  "status": "pending_confirmation",
  "summary": "跨角色沟通训练报告：展示了良好的沟通协调能力",
  "data": {
    "abilityEvidence": [
      {
        "abilityKey": "communication",
        "summary": "在跨部门需求冲突场景中，用户提出了分阶段沟通、数据驱动的协调方案，表现出较强的沟通能力",
        "sourceType": "simulation",
        "sourceRef": "sim-session-abc123",
        "confidence": 0.85
      },
      {
        "abilityKey": "businessProduct",
        "summary": "能够从业务价值角度分析需求优先级，区分核心需求与锦上添花功能",
        "sourceType": "simulation",
        "sourceRef": "sim-session-abc123",
        "confidence": 0.78
      }
    ]
  },
  "evidence": [
    {
      "round": 3,
      "userResponse": "我认为应该先理解双方的核心诉求...",
      "evaluation": "展现了数据驱动的决策思维"
    }
  ],
  "sources": [],
  "assumptions": ["评估基于单次模拟训练的表现，可能不完全反映真实工作能力"],
  "warnings": [],
  "requiresUserConfirmation": true,
  "baseVersion": 3,
  "nextActions": ["查看完整能力证据", "制定针对性提升计划"]
}
```

### abilityEvidenceDataSchema 字段约束

| 字段 | 类型 | 必填 | 约束 |
|------|------|------|------|
| `abilityEvidence` | array | ✅ | 至少 1 条 |
| `abilityEvidence[].abilityKey` | string | ✅ | 非空字符串 |
| `abilityEvidence[].summary` | string | ✅ | 1-500 字符 |
| `abilityEvidence[].sourceType` | string | ✅ | 固定 `"simulation"` |
| `abilityEvidence[].sourceRef` | string | 否 | 可选引用 |
| `abilityEvidence[].confidence` | number | ✅ | 0-1 之间 |

### 六项固定能力键（abilityKey 允许值）

仅允许以下六个能力键：
- `aiTooling` — AI 工具使用
- `roleFoundation` — 岗位基础
- `dataAnalysis` — 数据分析
- `businessProduct` — 业务产品
- `communication` — 沟通协作
- `projectPractice` — 项目实践

## 处理流水线

```
simulation_turn (status=success)
  → validatedAgentArtifactV1Schema ✅（simulationTurnDataSchema 校验通过）
  → ingestion：不创建候选
  → 轮次内容追加到会话记录

simulation_report (status=pending_confirmation)
  → validatedAgentArtifactV1Schema ✅（abilityEvidenceDataSchema 校验通过）
  → ingestion：创建 ability_evidence 候选（status=pending）
  → 用户确认后 → accept → 写入 AbilityEvidence 表（status=confirmed）
```

## 常见错误

1. ❌ `simulation_report` 使用 `status: "success"` —— 不会创建候选，证据丢失
2. ❌ `data` 中包含 `score`、`strengths`、`improvements` 等字段 —— schema 拒绝，只接受 `abilityEvidence`
3. ❌ `simulation_turn` 缺少 `isComplete: false` —— schema 拒绝
4. ❌ `abilityEvidence` 为空数组 —— schema 拒绝（至少 1 条）
5. ❌ `abilityKey` 使用非六项能力键（如 `leadership`）—— schema 允许通过（仅 warning），但建议使用标准六键
