# V2画像评估

`taskType` 固定为 `profile_assessment`。开始节点三个文本参数必须绑定：`request`、`task_context_json`、`evidence_bundle_json`。

## 输出

`data` 只能包含 `patch`、`abilityEvidence`、`scores`、`strengths`、`gaps`、`missingInformation`，且至少包含一个有效 `patch` 字段、一条 `abilityEvidence` 或一个 `score`。

```json
{
  "schemaVersion": "1.0",
  "taskType": "profile_assessment",
  "status": "pending_confirmation",
  "summary": "根据课程项目补充数据分析能力证据",
  "data": {
    "abilityEvidence": [
      {
        "abilityKey": "dataAnalysis",
        "summary": "课程项目中独立完成数据清洗和可视化",
        "sourceType": "course_project",
        "sourceRef": "project-1",
        "confidence": 0.75
      }
    ],
    "scores": {
      "dataAnalysis": {
        "value": 68,
        "evidence": "课程项目可追溯到清洗、分析和可视化步骤",
        "confidence": 0.75
      }
    },
    "strengths": ["能完成端到端分析练习"],
    "gaps": ["缺少真实业务项目"],
    "missingInformation": ["团队协作经历"]
  },
  "evidence": ["课程项目材料"],
  "sources": [],
  "assumptions": [],
  "warnings": [],
  "requiresUserConfirmation": true,
  "baseVersion": 3,
  "nextActions": ["确认后写入能力证据"]
}
```

## 规则

- `scores` 是六维键对象，不是数组；每项必须是 `{ value, evidence, confidence }`。
- 六维键固定为 `aiTooling`、`roleFoundation`、`dataAnalysis`、`businessProduct`、`communication`、`projectPractice`。
- 没有证据的维度省略，不输出 0 分；个人证据不得引用市场或职业基线。
- `patch` 只包含用户本轮明确需要变更的字段，不用 `null` 覆盖未提及字段。
- `baseVersion` 取当前画像版本；未知或缺失时返回 `needs_input`，不得生成可保存候选。
- `pending_confirmation` 必须 `requiresUserConfirmation=true`。

## 代码节点

代码节点由 `npm run tbox:bundle` 从当前后端契约生成，使用导出目录中本工作流的 `code-node.js` 全文。不得从历史文档复制旧代码。代码输入绑定见同目录 `绑定步骤.md`。

结束节点只返回 `artifact`。
