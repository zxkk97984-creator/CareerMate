# V2职业探索

`taskType` 固定为 `career_exploration`。开始节点三个文本参数必须绑定：`request`、`task_context_json`、`evidence_bundle_json`。

## 只读比较与模板候选的边界

- 普通方向比较是只读报告：`status="success"`、`requiresUserConfirmation=false`、`baseVersion=null`。
- 只有用户明确要求把新职业提交为公共资料时，才在同一 artifact 中带 `roleKey`、`roleName` 等模板字段，并改为 `pending_confirmation` + `requiresUserConfirmation=true`；接受后只创建待管理员审核的 `RoleDraft`。
- 未知职业缺少可靠市场信息时返回 `needs_input`，不要编造 roleKey、薪资或岗位要求。

## 规则

- `options` 为 1–10 项，每项 `roleName` 必填；没有评分方法时省略 `fitScore`。
- `recommendedOrder` 只能引用 `options` 中实际存在的 key/名称。
- 市场事实必须来自 `evidence_bundle_json.marketEvidence`；本地岗位样本只标为“未核验本地样本”。
- 不自动改变用户目标，不把一次比较报告写成正式画像。
