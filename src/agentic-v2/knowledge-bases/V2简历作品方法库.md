# V2简历作品方法库

## 说明

本文件提供简历编写、作品集构建和职业展示的方法与模板。适用于各职业阶段的求职者，内容可针对具体职业进行调整。

### 使用方法

每个方法/模板独立成节，可直接引用或组合使用。建议按以下顺序使用本库：

1. 简历结构模板（方法 1-2）——搭建简历基本框架
2. 职业专属优化（方法 3-4）——根据目标职业调整内容
3. 作品集构建（方法 5-6）——补充项目实证
4. 问题排查（方法 7-8）——检查并优化最终效果

## 方法 1：STAR 法则简历结构模板

### 概述

STAR 法则即 Situation（情境）、Task（任务）、Action（行动）、Result（结果），是书写简历工作经历的标准框架。

### 模板结构

#### 基本信息区

```
[姓名] | [求职意向]
[电话] | [邮箱] | [GitHub/作品链接]
[所在城市] | [到岗时间]
```

> 注意：本数据集不包含真实个人信息，使用时请勿填写真实姓名、电话和邮箱。

#### 个人简介（4-6 行）

```
[职业定位] + [核心优势] + [关键成就数字] + [主要技能领域]
```

**示例：** 5 年数据分析经验，擅长用户行为分析和增长策略制定。主导搭建公司核心指标体系，通过分析驱动产品改进，实现留存率提升 15%。精通 SQL、Python 及 BI 工具。

#### 工作经历（每段按 STAR 结构）

```
[公司名称] | [职位] | [在职时间]

S：项目/任务的背景和挑战
T：你承担的角色和具体任务目标
A：你采取的具体行动和方法（重点写 3-5 点）
R：取得的量化结果（用数据支撑）
```

**示例：**

```
某电商平台 | 数据分析师 | 2023.01 - 2025.06

S：平台用户留存率连续 3 个月下滑，业务部门无法定位根因
T：负责搭建留存分析框架，定位核心流失环节
A：
- 设计用户分层模型，按活跃度和消费行为划分 5 类用户群体
- 构建用户行为漏斗，识别出注册后第 3 天流失率最高（42%）
- 通过 A/B 测试验证了新用户引导流程优化的有效性
R：
- 优化后注册次日留存率从 55% 提升至 63%
- 季度挽回流失用户约 2.3 万人，贡献 GMV 约 180 万
```

#### 项目经历

```
[项目名称] | [角色] | [时间]

- 项目目标：[一句话说明]
- 我的职责：[具体负责内容]
- 技术/方法：[使用的工具、技术或方法论]
- 成果：[量化结果]
```

#### 技能清单

```
- [技能类别]：[具体技能 1]、[具体技能 2]、[具体技能 3]
- [技能类别]：[具体技能 1]、[具体技能 2]、[具体技能 3]
```

## 方法 2：量化成就写作模板

### 概述

使用数据量化成就是简历写作的核心原则。本模板提供将模糊描述转换为量化成就的方法。

### 转换规则

| 模糊描述 | 量化转换方法 | 示例（量化前） | 示例（量化后） |
|----------|-------------|----------------|----------------|
| 提高了效率 | 增加百分比/时间对比 | 优化了数据查询流程 | 优化 SQL 查询流程，执行时间从 30 分钟降至 3 分钟 |
| 参与某项目 | 明确角色和贡献 | 参与了用户增长项目 | 作为核心成员搭建用户增长分析模型，覆盖 50 万用户 |
| 负责某工作 | 明确范围和度量 | 负责数据分析工作 | 负责 3 条业务线的数据分析，月产出报告 15+ 份 |
| 做了优化 | 明确优化指标 | 优化了推荐效果 | 优化推荐算法排序策略，CTR 提升 8.2% |

### 量化数据来源

- 公司内部报表和仪表盘
- 项目管理工具（Jira/Asana）的数据
- 代码仓库的贡献统计（PR 数量/代码行数）
- 用户反馈和 NPS 评分
- A/B 测试结果

### 注意事项

- 数据必须真实可查证
- 没有精确数据可使用合理估算（标明「约」）
- 使用具体数字而非「显著」「大幅」等模糊词汇
- 优先使用相对指标（百分比）而非绝对指标

## 方法 3：数据分析师简历重点

### 核心卖点

数据岗简历需要突出三个核心维度：

| 维度 | 重点内容 | 如何展示 |
|------|----------|----------|
| 技术能力 | SQL、Python、统计学、BI 工具 | 在工作经历中描述具体使用场景 |
| 业务理解 | 行业知识、指标体系、分析框架 | 展示从数据到业务决策的完整链路 |
| 沟通呈现 | 报告撰写、跨部门协作、汇报 | 量化报告产出和影响力 |

### 简历加分项

- 包含完整的分析项目闭环（发现问题-分析-建议-效果跟踪）
- 展示 SQL 复杂查询能力（窗口函数、CTE 等）
- 体现对业务指标的深入理解（不只是取数工具人）
- 有自动化提效的案例（脚本/报表自动化）

### 示例技能清单

```
- 数据分析：SQL（复杂查询、窗口函数、查询优化）、Python（Pandas、NumPy）
- 数据可视化：Tableau、Power BI、Metabase
- 统计方法：A/B 测试设计、假设检验、回归分析
- 业务工具：Excel、数据产品设计、指标体系搭建
```

## 方法 4：AI 产品经理简历重点

### 核心卖点

AI 产品岗需要展示技术理解与产品能力的结合：

| 维度 | 重点内容 | 如何展示 |
|------|----------|----------|
| 技术理解 | LLM/RAG/Agent 原理、模型调优 | 在项目中展示技术方案选型能力 |
| 产品能力 | 需求定义、交互设计、PRD | 体现 AI 产品的独特设计考量 |
| 落地经验 | 从 0 到 1 的产品经验、上线效果 | 展示量化业务成果 |

### 简历加分项

- 有 AI 产品从 0 到 1 的经验
- 展示模型评估和数据标注的管理经验
- 有处理 AI 产品特有问题的案例（幻觉、安全、伦理）
- 能说明技术边界和产品决策的权衡过程
- 有提示词工程的实际应用成果

### 示例技能清单

```
- AI 技术：LLM 应用开发、RAG 方案设计、提示词工程
- 产品工具：Figma、Axure、ProcessOn
- 数据分析：数据驱动决策、模型评测、A/B 测试
- 管理能力：产品路线图、跨团队协作、敏捷管理
```

## 方法 5：作品集构建指南

### 作品集结构

一个完整的作品集应包含以下层次：

| 层次 | 内容 | 目的 |
|------|------|------|
| 顶层 | 个人简介 + 核心技能 + 联系方式 | 快速建立印象 |
| 项目层 | 3-5 个核心项目 | 展示深度和广度 |
| 细节层 | 每个项目的技术细节和成果 | 证明能力 |
| 附证层 | 证书、文章、开源贡献 | 增强可信度 |

### 每个项目的描述结构

```
## [项目名称]

### 项目背景
[1-2 句说明项目来源和要解决的问题]

### 我的角色
[产品经理 / 技术负责人 / 核心开发者]

### 方案与执行
[2-4 点说明做了什么，怎么做的，遇到什么挑战]
- 关键决策点 1：[方案选型的考量]
- 关键决策点 2：[技术或产品上的权衡]

### 成果与数据
[量化结果，用数字说话]

### 反思
[学到了什么，如果重来会怎么做]
```

### 作品集形式选择

| 形式 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| PDF 作品集 | 便于发送和打印 | 缺乏交互性 | 邮件投递 |
| 个人网站 | 可交互、展示全面 | 维护成本高 | 技术岗 |
| GitHub | 代码可见、协作记录 | 非技术人员看不懂 | 开发岗 |
| 在线演示 | 直观展示功能 | 需持续维护 | 产品/设计岗 |

## 方法 6：GitHub 主页优化指南

### 需要优化的元素

| 元素 | 优化方法 | 注意事项 |
|------|----------|----------|
| 个人简介 | 使用 README.md Profile 展示技能栈和成就 | 保持简洁，使用图标增强可读性 |
| README | 每个项目必须有高质量的 README | 包含截图、安装说明、使用示例 |
| 提交历史 | 保持规律提交，信息清晰 | 不要拆分或伪造提交 |
| 项目组织 | 使用 Topics 和 Pin 突出重点项目 | 置顶 3-6 个最能代表能力的项目 |
| 文档质量 | 代码注释、API 文档、使用说明 | 中文注释为主，关键部分保留英文术语 |

### Profile README 模板

```markdown
# 你好！欢迎来到我的 GitHub 👋

## 关于我
- [当前职位] 专注于 [领域]
- 擅长 [技能 1]、[技能 2]、[技能 3]
- 正在学习 [新技术]

## 技能
[可以使用徽章图标展示技能]

## 项目精选
[置顶项目列表及简要说明]

## 贡献
- [开源项目贡献]
- [技术文章]
- [社区参与]
```

### 常见优化点

- 使用 GitHub Actions 自动化 CI/CD 流程
- 项目添加 License 文件
- 使用 .gitignore 管理依赖
- 保持依赖版本更新
- 添加贡献指南（CONTRIBUTING.md）

## 方法 7：AIGC 内容运营简历重点

### 核心卖点

AIGC 内容运营岗需要突出三个维度：

| 维度 | 重点内容 | 如何展示 |
|------|----------|----------|
| 工具能力 | AI 工具的熟练度和组合使用 | 展示工具生态理解和实际产出效率 |
| 内容质量 | 提示词设计、内容把控、原创策略 | 量化内容产出的质量和曝光数据 |
| 运营思维 | 数据驱动选题、分发策略、用户增长 | 展示阅读量/互动率等运营指标 |

### 简历加分项

- 展示 AI 工具组合使用的工作流（如 AI 出图+文案+排版）
- 有提示词优化案例（从差到好的对比）
- 体现内容数据复盘和策略迭代能力
- 有批量内容生产和质量把控的经验
- 展示对 AI 内容检测和去 AI 痕迹化的理解

### 示例技能清单

```
- AIGC 工具：ChatGPT/GPT-4、Midjourney/Stable Diffusion、剪映 AI
- 内容平台：微信公众号、小红书、抖音、知乎
- 数据分析：内容效果分析、用户画像、热点挖掘
- 辅助技能：SEO 优化、基础 PS/AE、文案写作
```

## 方法 8：常见简历错误与改进方法

### 错误清单

| 序号 | 常见错误 | 问题描述 | 改进方法 |
|------|----------|----------|----------|
| 1 | 缺少量化结果 | 只写做了什么，没写取得了什么效果 | 每段经历至少包含 2 个量化成果 |
| 2 | 职责描述过多 | 罗列日常职责而非成就 | 以 STAR 法则改写，突出行动和结果 |
| 3 | 关键词堆砌 | 大量技能词但无实际案例支撑 | 每个关键技能匹配一个使用场景 |
| 4 | 篇幅过长 | 超过 2 页，包含无关信息 | 控制在 1-2 页，删减 3 年以上的非核心经历 |
| 5 | 格式混乱 | 字体字号不统一，排版拥挤 | 使用统一模板，适当留白 |
| 6 | 缺少针对性 | 所有岗位投递同一份简历 | 根据目标岗位调整重点和关键词 |
| 7 | 夸大或虚假 | 能力描述与实际不符 | 诚实描述，用面试中能展开的案例说话 |
| 8 | 忽略软技能 | 只有硬技能没有软技能体现 | 在合作项目中体现沟通、领导力等软技能 |

### 自我检查清单

投递前逐项检查：

- [ ] 格式统一：字体、字号、间距一致
- [ ] 无错别字：全文检查拼写和语法
- [ ] 量化充足：80% 以上的成就项有数据支撑
- [ ] 关键词匹配：包含目标岗位 JD 中的重要要求
- [ ] 时间连续：无不明原因的时间断档
- [ ] 信息有效：不包含无关的个人信息
- [ ] 一页以内：初级岗位建议一页，资深岗位不超过两页
- [ ] PDF 格式：不使用 Word 格式投递
