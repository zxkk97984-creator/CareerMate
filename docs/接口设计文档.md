# CareerMate 当前接口设计

> 本文描述当前代码实际提供的接口。路由、输入校验和状态行为以 `src/app/api/**/route.ts`、`src/lib` 服务层以及 `prisma/schema.prisma` 为最终真源。

## 1. 接口边界

```text
浏览器页面 / Kurisu 浮窗
        ↓ Cookie session
Next.js Route Handlers
        ↓
业务服务层 + Zod 校验 + 用户所有权检查
        ↓
Prisma / SQLite
        ↓ 可选
TBox Mock / Manual / API 或 Agentic V2 business_data
```

浏览器不直接调用百宝箱。百宝箱 API Key、Agent ID 和 dataset ID 只能由服务端环境变量提供。

当前产品聊天主入口是：

```text
POST /api/chat/conversations/:id/stream
```

`/chat` 页面当前重定向到 `/dashboard`；`/api/tbox/chat*` 是诊断/兼容接口，不是主聊天入口。

## 2. 通用约定

### 2.1 Base URL

```text
开发：http://localhost:3000
E2E：http://127.0.0.1:3100
```

### 2.2 认证

Web API 使用 `careermate_session` httpOnly Cookie：

- `requireCurrentUser()`：要求登录。
- `requireAdmin()`：要求登录且 `User.role === "admin"`。
- 所有业务查询和写入都必须绑定当前用户 ID。

服务端入口：

- `src/lib/auth.ts`
- `src/lib/session-security.ts`
- `src/app/api/auth/*`

### 2.3 通用响应

成功：

```json
{
  "ok": true,
  "data": {},
  "meta": {}
}
```

失败：

```json
{
  "ok": false,
  "error": {
    "code": "INVALID_INPUT",
    "message": "请求参数不合法",
    "detail": {}
  },
  "meta": {
    "requestId": "uuid"
  }
}
```

统一构造函数位于 `src/lib/api.ts`。具体接口可能使用 `UNAUTHORIZED`、`FORBIDDEN`、`NOT_FOUND`、`CONFLICT`、`INVALID_INPUT`、`VALIDATION_ERROR` 等领域错误码。

## 3. 认证与工作台聚合

### `POST /api/auth/register`

请求字段：

```json
{
  "username": "student_lin",
  "displayName": "小林",
  "password": "至少 6 位"
}
```

创建用户和空画像，创建登录态，返回用户 DTO 和 `nextPath`。

### `POST /api/auth/login`

请求字段：`username`、`password`。密码通过 bcrypt 校验，成功后创建登录态并返回 `nextPath`。

### `POST /api/auth/logout`

删除当前 session，并返回：

```json
{ "ok": true, "data": { "loggedOut": true } }
```

### `GET /api/me`

工作台首次加载的聚合接口，返回：

- 当前用户。
- 用户画像。
- 岗位匹配度和弱项。
- 最近进度日志。
- 活跃画像引导会话。
- 当前 AI 运行模式。

工作台还会并行请求计划、资源、记忆、候选、V2 候选、模拟和管理员数据。

## 4. 画像引导与画像

### `POST /api/onboarding/chat`

请求：

```json
{
  "message": "我大三，统计学专业，想做数据分析，每周有 8 小时",
  "conversationId": "可选的本地画像会话 ID"
}
```

服务端会：

1. 创建或校验当前用户的 `OnboardingConversation`。
2. 从自然语言中提取阶段、专业、岗位、时间、偏好、经历和限制。
3. 合并 draft 并计算完整度。
4. 调用 TBox 适配层生成追问；失败时使用确定性追问。
5. 使用 `updatedAt` 条件更新，避免并发覆盖。

返回 `assistantMessage`、`conversationId`、`draft`、`profileCompleteness` 和 AI 执行元数据。

### `POST /api/onboarding/complete`

请求：

```json
{ "conversationId": "画像引导会话 ID" }
```

完整度至少 0.8 后才允许完成。服务端事务会：

- 将画像引导会话标记为 `completed`。
- 通过画像修改服务写入 `UserProfile`。
- 递增画像版本号。
- 设置 `onboardingCompleted=true`。
- 写入 `ProgressLog`。

### `GET /api/profile`

返回当前用户画像 DTO。

### `PATCH /api/profile`

允许用户直接修改画像白名单字段。请求会经过 `profilePatchSchema`，成功后递增画像版本并写入进度日志。

### `GET /api/profile/candidates`

返回当前用户的旧版 `ProfileUpdateCandidate`，支持 `status` 过滤。

### `PATCH /api/profile/candidates`

请求包含：

```json
{
  "candidateId": "候选 ID",
  "action": "accept 或 reject"
}
```

接受时会校验候选状态、画像版本和用户所有权，再将候选 patch 投影到画像。

## 5. 对话与 SSE

### `GET /api/chat/conversations`

查询当前用户未删除的会话，按 `lastMessageAt` 倒序，支持 `cursor` 和 `limit`。

### `POST /api/chat/conversations`

创建当前用户的新会话，可选 `title`；未提供时使用 `新对话`。

### `GET /api/chat/conversations/:id`

返回当前用户拥有的会话详情。跨用户或不存在时返回 `NOT_FOUND`。

### `PATCH /api/chat/conversations/:id`

修改会话标题，长度限制为 1–60 个字符。

### `DELETE /api/chat/conversations/:id`

软删除会话，将状态设置为 `deleted`。

### `GET /api/chat/conversations/:id/messages`

返回消息历史，支持 `before` 游标和 `limit`，消息中的 `parts`、执行元数据和上下文元数据都会经过安全解析。

### `POST /api/chat/conversations/:id/stream`

请求：

```json
{
  "message": "根据我的最新情况调整职业路径",
  "clientRequestId": "UUID v4",
  "actionId": "可选快捷操作 ID",
  "interaction": {
    "surface": "career_path",
    "action": "regenerate_plan",
    "targetRef": "可选的当前页面对象引用"
  }
}
```

有状态轮次默认开启，由 `TurnService` 负责：

- 请求幂等。
- 并发轮次锁定。
- 已完成轮次 replay。
- 用户消息和助手占位消息的两阶段持久化。
- 失败、停止和完成状态。

SSE 事件主要包括：

```text
context
delta
artifact
done
error
```

正常响应头为 `text/event-stream; charset=utf-8`。前端解析器位于 `src/lib/tbox/frontend-sse.ts`。

## 6. 计划与学习路线

### `POST /api/plans/generate`

根据当前用户画像创建或生成计划。没有目标岗位时返回 `PROFILE_INCOMPLETE`。

计划生成服务使用以下状态：

```text
generating → processing → pending → active
                         ↘ generation_failed
```

新计划通常先进入 `pending`，由用户确认后激活。

### `GET /api/plans/current`

返回：

- 当前 `active` 计划。
- 最新 `pending` 计划。
- 最近一次生成的 AI 执行元数据。

### `GET /api/plans/:planId`

返回当前用户拥有的指定计划。

### `POST /api/plans/:planId/decision`

请求：

```json
{ "action": "accept 或 reject" }
```

接受 pending 计划时会通过用户条件和版本条件原子更新旧计划与新计划状态。

### `PATCH /api/plans/:planId/tasks/:taskId`

请求：

```json
{ "status": "not_started | in_progress | done | delayed" }
```

服务端会解析 36 个月兼容数组，确认任务 ID 唯一后更新任务状态并记录进度。

### `GET /api/learning-routes/current`

返回当前用户最新的有效 `LearningRoute`。学习路线是独立的版本化模型，不等同于 `CareerPlan`。

## 7. 模拟训练

### `GET /api/simulations`

返回当前用户的训练会话。

### `GET /api/simulations/scenarios`

根据用户目标岗位和 `RoleTemplate` 返回可用训练场景。

### `POST /api/simulations`

请求：

```json
{ "scenarioType": "cross_role_communication" }
```

创建 active `SimulationSession`，返回会话和开场消息。

### `POST /api/simulations/:sessionId/messages`

请求：

```json
{ "message": "至少 5 个字符的训练回答" }
```

最多 6 轮；服务端使用当前 transcript 生成下一轮问题，并使用 `updatedAt` 和 `turnCount` 防止并发覆盖。

### `POST /api/simulations/:sessionId/complete`

至少完成 3 轮后允许评分。报告必须通过结构化 Schema，随后在事务中保存：

- 分数。
- 优势和改进项。
- 能力影响。
- 可选能力证据候选。
- `ProgressLog`。

降级评分可以保存结果，但不会创建正式能力候选。

## 8. 资源、记忆和隐私

### `GET /api/resources`

支持 `roleKey`、`abilityKey` 和 `type` 筛选，只返回通过来源安全规则的资源。

### `/api/memories`

- `GET`：读取当前用户记忆。
- `POST`：创建用户手动记忆。
- `PATCH`：通过 query 中的 `id` 更新记忆。
- `DELETE`：通过 query 中的 `id` 删除记忆。

### `/api/memory/:id`

- `GET`：读取单条记忆。
- `PATCH`：编辑内容或敏感度。
- `DELETE`：删除记忆。

### `POST /api/memory/:id/decision`

接受或拒绝待确认记忆提议。

### `POST /api/memory/toggle`

请求：

```json
{ "enabled": true }
```

关闭长期记忆不会删除已有记忆，只会阻止新的记忆写入。

### `GET /api/privacy/export`

导出当前用户成长数据，不包含 `passwordHash`。

### `DELETE /api/privacy/account-data`

请求必须包含：

```json
{ "confirmation": "CLEAR_MY_DATA" }
```

事务删除画像成长数据、对话、计划、训练、记忆、候选和进度，但保留用户账号、角色和登录态。

## 9. Agentic V2 候选

### `GET /api/agentic-v2/candidates`

查询当前用户候选，支持 `status` 和 `candidateType` 过滤。

### `GET /api/agentic-v2/candidates/:candidateId`

读取当前用户拥有的候选详情。

### `POST /api/agentic-v2/candidates/:candidateId/decision`

请求：

```json
{ "decision": "accept 或 reject" }
```

接受候选时依次执行：

1. 当前用户所有权检查。
2. `AgentArtifactV1` 校验。
3. candidateType 与 taskType 兼容性校验。
4. 业务 data Schema 校验。
5. `baseVersion` 冲突检查。
6. pending 原子 claim。
7. 事务化投影到画像、计划、路线、记忆、能力证据或岗位草稿。

候选状态包括：

```text
pending → applying → accepted
pending → rejected
```

重复同一决定保持幂等，相反决定返回冲突。

## 10. 管理员岗位草稿

管理员接口：

- `GET /api/admin/role-drafts`
- `POST /api/admin/role-drafts`
- `PATCH /api/admin/role-drafts`
- `POST /api/admin/role-drafts/generate`
- `PATCH /api/admin/role-drafts/:id`
- `POST /api/admin/role-drafts/:id/approve`
- `POST /api/admin/role-drafts/:id/reject`

草稿必须通过 `roleDraftContentSchema`，审核通过后才写入 `RoleTemplate`。

## 11. TBox 与保留 MCP 接口

### `/api/tbox/chat`

非流式 TBox 诊断接口。

### `/api/tbox/chat/stream`

流式 TBox 诊断接口，当前产品聊天不直接使用。

### `/api/tbox/retrieve`

知识库检索诊断接口。

### `/api/mcp/*`

旧插件/MCP 兼容接口，包括课程、岗位、画像候选和进度更新。

### `/api/mcp/v2`

保留的 JSON-RPC MCP V2 基础设施。当前 Agentic V2 聊天使用脱敏 snapshot，不依赖该公网业务 MCP。启用前必须完成 Origin、Bearer Token、Scope、协议版本和跨用户隔离验证。

## 12. 模式和环境变量

基础模式：

```text
TBOX_MODE=mock|manual|api
```

重要开关：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `CAREERMATE_AGENTIC_V2` | `false` | 启用 V2 snapshot + artifact 聊天路径 |
| `STATEFUL_CHAT_TURNS` | `true` | 启用幂等和 replay 的有状态聊天轮次 |
| `TBOX_STRUCTURED_MODE` | `disabled` | 旧 AgentResponse structured 路径；`terminal` 只在契约验证后启用 |
| `AGENT_OPERATIONS_V1` | `false` | 旧 structured operations 执行开关 |
| `PLAN_V2_WRITE` | `false` | 允许写入 V2 灵活计划 |
| `TBOX_CONTEXT_TRANSPORT` | `question_prefix` | `question_prefix`、`business_data` 或 `provider_history` |
| `TBOX_HISTORY_MODE` | `context_only` | 是否由 provider 管理历史 |
| `TBOX_SEARCH_ENGINE` | `false` | 基础 TBox 路径的搜索开关；V2 路径固定关闭 |

`.env.example` 是安全默认值模板，真实密钥不能提交。

```text

```

```bash
npm run secret:scan
npm run lint
npm run typecheck
npm run test
npm run test:migrations
npm run build
```

完整门禁：

```bash
npm run verify
```

历史接口、旧产品设计和平台发布计划不应覆盖当前代码行为；若发现冲突，应先更新本文或在文档中明确标注“历史设计”。
