# API 接口说明

校准日期：2026-09-11。页面与 API 同属 Next.js 应用。本文描述分组和关键行为；字段校验以对应 `src/app/api/**/route.ts` 及 `src/lib` 契约为准。

## 协议与身份

业务 JSON 返回 `{ ok: true, data, meta }` 或 `{ ok: false, error: { code, message }, meta }`。聊天 SSE 是例外，使用 `context`、`delta`、`artifact`、`heartbeat`、`done`、`error` 事件。请求受当前登录用户、资源所有权和参数校验约束。管理员及 MCP 入口有额外权限要求，不能将所有接口描述为同一种认证方式。

## 模拟训练与聊天

- `GET /api/simulations/scenarios`：推荐场景列表；`POST`：生成推荐、岗位或自定义场景预览。
- `POST /api/simulations`：接收 `scenarioType` 或完整 `scenarioSnapshot`，可带 `sourceType`、`sourceRef`、`roundLimit`；新增可选 `createConversation`、`requestId`。场景大厅传入 `createConversation=true` 和稳定请求 ID，响应包含 `session`、`openingMessage` 与 `conversationId`。
- `GET /api/simulations`：当前用户训练列表；`GET /api/simulations/:sessionId`：指定训练详情。
- `POST /api/simulations/:sessionId/conversation`：恢复或创建该训练的关联聊天，返回 `conversationId`；旧 transcript 按稳定标识导入，不重复插入。
- `POST /api/chat/conversations/:id/stream`：输入 `message`、`clientRequestId`，可带任务交互信息。后端按持久化训练关联决定是否调用训练服务，不能由客户端任意指定别人的训练。
- `POST /api/simulations/:sessionId/messages`：保留的模拟回答接口，使用共享服务；接收 `message`（5–4000 字符）和 `requestId`。
- `POST /api/simulations/:sessionId/complete`：至少 3 轮有效回答后生成报告。重复完成不重复生成候选或报告；校验失败可重试。
- 聊天详情增加 `simulation`，普通聊天返回 `null`。报告通过 `simulation_report_ref` 消息部件加载，已结束训练的后续讨论不再计入训练。

创建训练同时持久化场景/评分依据快照。开始前的预览不是正式训练；返回聊天正文也不代表评分或能力候选已保存。

## 兼容与平台边界

`/api/tbox/chat`、`/api/tbox/chat/stream`、`/api/tbox/retrieve` 和 `/api/mcp/*` 是兼容或诊断入口。主产品聊天使用会话型接口。百宝箱子工作流统一输入三个文本：`request`、`task_context_json`、`evidence_bundle_json`；代码节点另外接收绑定大模型输出的 `raw`，结束节点返回 `artifact`。

候选接受必须满足当前用户归属、允许状态、字段完整性与版本匹配。版本冲突时重新生成或刷新，不能绕过校验覆盖已有数据。完整架构见 [技术架构](architecture.md)。
