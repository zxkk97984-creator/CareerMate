## 2. 先配置 V2学习路线

打开该工作流编辑画布。保留四节点顺序：

```text
开始 → 大模型 → 代码 → 结束
```

### 2.1 开始节点：三个必填文本参数

| 参数名称 | 类型 | 必填 | 描述建议 |
|---|---|---|---|
| `request` | 文本/String | 是 | 本轮用户业务请求 |
| `task_context_json` | 文本/String | 是 | 后端提供的任务、版本、时间和预算上下文 JSON |
| `evidence_bundle_json` | 文本/String | 是 | 保持个人与外部来源独立的证据包 JSON |

旧“提问”参数不能继续作为唯一入口。先建立三个字段并完成后续引用替换，再移除不再被引用的旧参数。不要将三个参数设置成所有调用共用的固定样例。

### 2.2 大模型节点：正文与变量分别处理

1. 打开 `workflows/V2学习路线/llm-prompt.txt`，复制全文替换大模型提示词。
2. 滚到提示词末尾“本轮实际输入”。
3. 删除字面的 `{{request}}`，用大模型节点“添加输入项”/变量选择器选择 **开始 → request**。
4. 同样替换 `{{task_context_json}}` 和 `{{evidence_bundle_json}}`。
5. 保留大模型输出名称 **结果**，类型为文本。

不要手写历史 `input_...` 节点 ID，不把大括号占位当作已经绑定。具体生成的变量表示由平台决定。

**完成标志：三个位置都由选择器插入，能在运行详情看到实际值；没有裸的 `{{...}}` 槽。**

### 2.3 代码节点：四个输入，不是只有 raw

| 代码输入名称 | 取值 |
|---|---|
| `raw` | 大模型 → 结果 |
| `request` | 开始 → request |
| `task_context_json` | 开始 → task_context_json |
| `evidence_bundle_json` | 开始 → evidence_bundle_json |

复制 `workflows/V2学习路线/code-node.js` 全文到代码编辑器，不加 Markdown 围栏，不粘贴进大模型提示词。

该文件是本地打包的 JavaScript，已经带 Zod 与当前后端契约，导出 `main`；无需平台安装依赖。文件约 85 KB，平台代码编辑器是否接收这一大小尚未实测。若保存失败或内容被截短，停止这一组件的发布，把平台提示交给开发端，不删减校验强行保存。

代码输出设置：名称 **artifact**，类型 **结构化对象**，取值路径 **artifact**。

### 2.4 结束节点

输出名称填 **artifact**，值选择 **代码 → artifact**。

结束节点不引用大模型原始文本，不再拼正文，不添加 `CAREERMATE_ARTIFACT` 标签。标签只由主 Agent 对最终需要程序消费的结果添加一次。

### 2.5 先测代码节点，不消耗一次完整生成

在代码 IDE 右侧只有一个“输入”JSON 编辑框时，直接复制同目录 `code-node-smoke-input.json` **整个文件**到该框，保留双引号、反斜杠和转义字符，再点击“运行”。这里不要粘贴 `node -e` 终端命令，不要逐字段解码。

只有在“运行工作流”弹窗提供多个独立文本输入框时，才分别填写对应字符串的解码内容。这与代码 IDE 的整个 JSON 输入方式不同。

执行入口修复说明：旧交付文件使用 `module.exports`，平台测试出现 `No fetch handler defined`。新版以显式 `exports.main = async (event) => {` 开头，内部包含独立打包校验器，不依赖 Node 的 `module` 全局。已增加 exports-only 本地宿主测试。2026-09-09，用户在百宝箱复测 V2学习路线代码节点，返回与冒烟测试预期一致的 learning_route / needs_input，确认该节点新入口运行成功；其他七个工作流及完整生成链路仍需分别验收。不要根据报错自行增加 fetch 监听器。

代码节点正常输出应与同目录 `code-node-smoke-expected.json` 一致：

- 外层为 `{ "artifact": ... }`；
- `artifact.taskType` 为 `learning_route`；
- `artifact.status` 为 `needs_input`；
- `artifact.data.question` 为“请补充本轮训练或规划目标”。

这个测试故意使用 needs_input：证明手动测试 JSON 可被读取、代码执行和补问状态保留；不证明画布上的变量绑定已经正确，**不证明学习路线生成已完成**。

### 2.6 再测整个工作流

点击画布右上角“运行”，填写三个开始参数。以 `start-input-example.json` 为结构样例，其中版本、日期、职业均是合成测试值，不能用于真实用户。

本次 `request` 可以改为：

```text
这是合成测试。请为已有数据分析方向安排未来4周的SQL学习任务，每周最多6小时。每个任务明确产出和验收标准，并指定唯一id和weekIndex；不要联网或假装任务已经完成。
```

其余两项填写同一示例文件中解码后的 JSON。示例明确给出画像版本 3、活动计划版本 2、首次学习路线版本 null、4周和6小时预算。

检查最终输出：

- 足够生成时：`pending_confirmation`、`requiresUserConfirmation=true`、`baseVersion=2`、`data.baseRouteVersion=null`。
- 每项任务有唯一 id、周期内 weekIndex、投入、产出、验收；每周总时长 ≤ 6 小时。
- `stages[].tasks` 是任务来源；顶层 tasks 可空，若非空必须与阶段任务顺序与内容一致。
- 缺必要信息时可返回 needs_input，但应指出真正缺少的业务信息；不能仍要求已明确提供的预算或目标。
- 返回 error 时查看 `data.code`，不要只看绿色执行成功。

代码单测再将同一周任务时长改为超过 6 小时，应得到 `WEEKLY_BUDGET_EXCEEDED`，即使四周总量没有超过 24 小时。

**这一工作流的绑定、正常结果和错误结果都核对后，再继续其余工作流。**

## 3. 按同样方法配置其余七个工作流

每个工作流都使用自己目录里的 llm-prompt.txt 和 code-node.js，不能把学习路线代码复制给其他工作流。三个开始输入、四个代码输入及结束 artifact 设置相同。

| 工作流 | 关键行为与验收 |
|---|---|
| V2画像评估 | scores 为六维键对象；无证据维度省略；候选基于真实画像版本，缺版本不能保存 |
| V2职业探索 | 普通比较为 success 只读结果；只有明确提交公共职业资料才创建模板草稿候选；非法 options 对象应返回标准 error |
| V2职业规划 | data.plan 为完整 Plan V2，周期由用户确认，不固定3–5年；动作有具体对象、投入、成果、验收 |
| V2职场模拟 | 成功追问 round 等于 `task_context_json.expectedRound`，不再加一；sessionId/scenarioKey 匹配当前会话；needs_input/error 不按 success 再校验 |
| V2场景生成（新增） | 自定义/推荐场景不要求岗位 JD；只有依赖岗位样本的 job 场景缺 JD 才补问；只生成预览，不保存训练会话 |
| V2简历作品 | 当前兼容候选结构为 abilityEvidence；缺真实材料需补问，不把推断经历写成事实；完整审阅报告扩展不在此包中冒充已支持 |
| V2成长复盘 | 完整 data.plan + planPatch.parentPlanId；父计划 ID 与上下文一致；无法比较的能力不声称提升 |

`start-input-example.json` 是通用字段示例，不是每个工作流都齐全的业务数据。模拟成功测试必须提供同一场真实合成 transcript、保存的场景和 expectedRound；复盘必须提供完整原计划。不要将缺少这些内容的通用样例当作正常成功用例。

完成各个工作流后，在测试环境发布，并记录其实际发布版本。主 Agent 的三参数映射与资源引用将在第 6 步核对。

## 4. 配置研究员 V2P 和审查员 V2

主应用中的“子智能体设置”弹窗只修改名称/描述；完整人设需要打开对应子应用自己的编辑页面。不要在挂载描述框粘贴完整人设。

### 4.1 研究员 V2P

- 目标：CareerMate职业情报研究员V2P。
- 正文：`agents/研究员V2P.txt`。
- 开启“夸克搜索（含正文）”；普通搜索、内置联网和知识库检索不作为额外研究入口。
- 将正文中的插件标记通过编辑器引用选择器核对到实际含正文插件。
- 保留当前模型，先验证功能，不同时变更多个模型参数。

测试两次不同目的的合成请求即可：一次有调用方 currentTime，一次省略 currentTime。只调用一次含正文搜索；来源不足如实说明。有时间则原样记录；无时间则 collectedAt/accessedAt 为 null，不猜日期。

检查结果中的 sourceIds 与 sources.id 对应，日期、标题和 URL 可追溯到工具输出。搜索失败结果带 limitations，不算“市场结论已验证”。

### 4.2 审查员 V2

- 目标：CareerMate伦理证据审查员V2。
- 正文：`agents/审查员V2.txt`。
- 知识库挂载 V2伦理隐私规则库，并确认正文的引用块。
- 不挂载业务工作流、Skill 或联网插件，内置联网关闭。

分别测试缺少候选的输入，以及带有“保证录用”的合成候选。前者应 reject；后者应指出过度承诺并要求修订或拒绝，不能无条件 pass。输出包含 schemaVersion、verdict、issues、requiredChanges、riskFlags、confirmationRequired。

子应用测试通过后发布并记录版本，再更新主 Agent 引用。不要删除旧研究员 V2；主路由切换验证完成后才解除其重复挂载。

## 5. 核对知识库与 Skill

### 5.1 知识库

主应用核对七库：职业能力模板、学习资源、训练场景、伦理隐私规则、职业趋势研究、简历作品方法、认证机会。记录实际 dataset，不能只根据名称相同判断版本相同。静态趋势与认证资料不证明实时有效。

选择已有、能区分库内容的非敏感条目测试召回，不必为了测试向正式知识库新增记录。主 Prompt 按任务选择相关库，不要求每轮遍历七库。

### 5.2 Skill：后端优先，平台补充

这次提示词交付 ZIP 不包含两个 Skill 安装包。Skill 构建入口为：

```bash
npm run package:skills
```

输出：

```text
dist/skills/CareerMate职业证据解析.zip
dist/skills/CareerMate成长数据分析.zip
```

该构建命令重建本地 dist/skills 产物，不更新平台；已有需要留存的构建包先复制保存。平台在目标 Skill 的更新入口上传对应 ZIP，具体入口若与界面不符，先记录，不猜测。

包应包含根目录 SKILL.md、run.mjs、manifest.json、examples；入口为 `node run.mjs <input.json>` 或 stdin。依赖已打包，不使用 npm install。平台运行路径由实际挂载位置确定，不能写死 /tmp 或依赖前次沙箱创建的目录。

本地检查构建产物：

```bash
node dist/skills/.staging/evidence-parser/validate.mjs
node dist/skills/.staging/growth-analyzer/validate.mjs
```

**这里的 validate.mjs 是新构建脚本生成的 CLI 检查器，会执行 run.mjs；此前旧 ZIP 的同名文件只检查输入示例，两者不能混用。** 即便新检查器通过，统计语义仍要由核心单元测试与输出核对证明。

平台逐个验证核心函数原始输出和退出码。未成功的 Skill 保持关闭；主 Agent 使用后端 evidenceBundle.verifiedAnalysis，不让模型自算并冒充已执行。不要把“上传成功”“加载成功”当作核心函数执行成功。

## 6. 最后配置主 Agent

打开 CareerMate职业成长伙伴V2 编辑页面。

### 6.1 替换正文与插入引用

复制 `agents/主Agent.txt` 全文到“人设和指令”。保持当前模型；本次不以改温度代替协议修复。若存在独立 JSON 输出模式，主 Agent 保持支持正文加信封的模式。

平台引用操作：在对应位置输入 `{`，从已挂载资源列表选择。历史 `<|...|>` 标记粘贴后若只是普通文本，删掉该段并重选，直至显示平台引用块。

| 资源类型 | 正文中需核对的资源 |
|---|---|
| 知识库 | 七个 V2 知识库，各自职责对应 |
| 工作流 | 原有七个 + 新增 V2场景生成，共八个 |
| 子智能体 | 研究员 V2P、伦理证据审查员 V2 |
| Skill | 仅已经验证可运行的证据解析与成长分析 |

新增场景位置显示 `【绑定：工作流 V2场景生成】`，必须删除占位并从列表选择实际工作流。若用测试副本，选择副本并核对正文名称。**发布前搜索 `【绑定：`，不能残留占位。**

Skill 尚未验证时，删除该 Skill 的主动调用分支，改为“仅解释后端 verifiedAnalysis；缺少计算结果时报告不可用”，不要启用无法运行的挂载。待验证后再恢复对应引用。

### 6.2 挂载与取值

- 主 Agent 的直接夸克和内置联网入口关闭；公开实时研究交给 V2P。
- 八个已验证工作流、V2P、审查员开启；重复研究员 V2 在新路由验证后解除挂载，不删除应用。
- 主应用工作流设置应显示三个文本参数。使用模型识别时，描述清楚：request 是用户任务；另外两项是本轮快照的 JSON 字符串，不能设为固定示例。
- 实际上下文可能通过 business_data 或 question_prefix 提供。两种都以本次后端传入为准，不能仅因 API 字段没有 business_data 就说无上下文。
- 缺 taskContext/evidenceBundle 是后端传参或绑定问题，应要求重新加载，不让用户手填版本。

### 6.3 输出验收

普通闲聊只给正文；专用页面需要的 success 报告和场景也有一个 Artifact 信封，但不创建候选。候选为 pending_confirmation 且 requiresUserConfirmation=true，版本来自真实上下文。主 Agent 不重复输出中间 JSON，不把示例分数、周期或职业当用户事实。

审查员 revise 最多修订并复审一次；reject 或仍失败不输出可写候选。提示词声明不得写记忆，不代表平台自动提取后台已关闭。

V2场景生成必须重新复制本次生成的 `workflows/V2场景生成/llm-prompt.txt` 和 `workflows/V2场景生成/code-node.js`。新版代码节点会从前后说明、Markdown 代码围栏、`<CAREERMATE_ARTIFACT>` 标签或结构化对象中提取 artifact，再执行同一套 Zod 校验；仍不能跳过 `schemaVersion="1.0"`、字符串数组和合法 JSON 要求。只替换大模型提示词而不替换代码节点，仍可能出现 `INVALID_JSON`。如果页面仍显示“场景生成已降级为本地模板”，先查看平台最终节点的原始输出，不要只改本地代码。

## 7. 发布与本地联调

唯一发布顺序：

```text
记录回退版本
→ 工作流测试并发布
→ 子智能体测试并发布
→ 核对可用 Skill 与知识库
→ 主 Agent 草稿绑定与调试
→ 发布主 Agent
→ 已发布 API 联调
```

子资源与主应用版本之间可能独立变化，记录每一项，不只记主应用版本。不要根据“当前配置为最新”判断草稿已经发布。

平台调试预览没有 CareerMate 后端快照。公共咨询可直接测试；私人画像/计划功能需要合成完整输入，或从本地产品发起。没有快照而拒绝生成可保存候选，不是调用失败。

本地已发布 API 至少验证：

| 用例 | 要看到的证据 |
|---|---|
| 普通问题 | 有正文，不为了回答遍历全部工具 |
| 当前公开信息 | 研究员实际调用含正文插件，来源与结果对应 |
| 学习路线 | 三参数实值、合法周安排、完整候选；未接受不生效 |
| 自定义场景 | 无岗位 JD 仍可预览，开始后保持场景与评分快照 |
| 模拟训练 | 同一会话、正确轮次、真实回答报告，不重复开场或计分 |
| 确认/拒绝 | 拒绝不改正式数据；接受后才写入；过期版本不覆盖 |

查看节点时：进入已有“执行过程”，在左上列表选具体节点，再看下方输入/输出；列表有独立滚动条。Skill 加载、文件读取、沙箱运行是不同节点，安全校验 PASSED 与业务计算无关。

如果本地报连接错误，保留请求关联信息交给开发端查服务端原因，不通过重复发布 Prompt 试错。Mock/manual 结果不算发布 API 验收通过。

## 8. 记忆单独验证，不顺手清理正式记录

使用明确的测试用户和合成偏好，不使用真实用户资料。保留应用级开关原状态；涉及关闭应用级记忆时优先使用隔离测试应用，避免影响其他用户。

| 测试 | 方法与判断 |
|---|---|
| M01 同会话基线 | A 会话告诉一个合成偏好并询问；只能证明历史可用，不能证明长期记忆 |
| M02 同用户新会话 | 使用同 user_id、新 conversation_id，确保本地快照与消息中没有该偏好，再询问；同时检查平台记录/召回节点 |
| M03 跨用户 | 独立 user_id、新会话、无 A 数据快照；B 不应取得 A 的偏好。切换本地 UI 账号不等于已确认平台 user_id 不同 |
| M04 编辑/删除测试记录 | 仅操作刚创建的测试记录；用新会话再次查询，排除旧会话历史。分别记录平台与本地变化 |
| M05 平台关闭 | 仅在隔离环境关闭并恢复；分别测停止新提取与是否继续召回旧记录，不预设两者相同 |
| M06 本地关闭 | 关闭本地记忆后查候选/正式记录及发送快照；平台自动记忆行为另记，不能当作已同步关闭 |
| M07 本地失效处理 | 编辑/删除本地测试记忆后核对后续请求不再注入旧内容；远端历史仍能回答旧信息须单独解释 |
| M08 发布回归 | 在实际发布版本复测关键隔离/关闭行为，不用控制台草稿结果替代 |

缺少不同平台用户身份或可观察请求时将测试标“未验证”，不要据一次聊天记得内容就宣称隔离通过。平台关闭/删除不可验证时，只承诺本地确认记忆的控制范围，平台旧记录处置另行确认；不批量删除真实记忆。

## 9. 本地资源与岗位数据：可选，不是平台配置前置步骤

资源和岗位增量导入由开发端核实后执行，本指南不要求操作者为配置 Prompt 运行数据库写入。禁止 seed 重置。

BOSS 数据包含多个批次，不要将所有文件统一标为 2026-08-24。需要导入时先核实目标目录和批次，再 dry-run；只有确认的批次日期才传 collected-at，未知则省略。不要上传原始 CSV 到主 Agent。月薪、日薪、多薪制按既定解析口径分别处理。

本地 ResourceItem 与平台学习资源库不是自动同步机制；平台库已挂载也不能证明本地资源页已经有内容。

## 10. 遇到问题先定位，不猜改法

| 现象 | 下一步 |
|---|---|
| 标记是普通文字 | 输入 `{` 重选实际资源；确认已挂载 |
| 输入槽没有值 | 检查大模型变量选择器与四个代码输入，不能只看连线 |
| INVALID_WORKFLOW_INPUT | 核对三个开始参数是否实际传入及 JSON 内容，不填空对象绕过 |
| TASK_CONTEXT_MISMATCH | 核对 workflow/taskType；普通聊天路由需同步本次任务类型，版本不可改 |
| VERSION_MISMATCH / ROUTE_VERSION_MISMATCH | 重新加载当前快照；不手改版本通过 |
| WEEKLY_BUDGET_EXCEEDED | 调整对应周任务，不增加用户未确认的预算 |
| 代码无法粘贴或保存 | 记录平台限制与文件字节数，暂不发布；不要自行删除 Zod 校验 |
| 模型返回 needs_input | 先看缺口是否真实；示例不是所有任务的完整输入 |
| 沙箱安装/目录失败 | 新包不应安装依赖；核对 run.mjs 与单次调用，不使用旧源码运行方法 |
| 平台成功、本地失败 | 对照最终 Artifact、后端契约和发布版本；保留原始节点结果 |
| 场景生成降级为本地模板 | 检查主 Agent 是否实际调用 V2场景生成工作流；确认平台已上传新版 `workflows/V2场景生成/code-node.js`；核对结束节点 artifact 是否有 schemaVersion、字符串数组和合法 JSON；不要用主模型直接补写 |

回退恢复上一组验证过的主应用、工作流、子智能体、Skill 和知识库引用。平台提示词回退不需要重置本地数据库；数据库回滚由开发端根据实际迁移单独处理。
