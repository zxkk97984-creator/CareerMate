# CareerMate 百宝箱配置清单

> 版本：v1.0  
> 用途：指导在蚂蚁百宝箱企业版中配置 CareerMate 智能体、工作流、知识库、插件、评测和多端发布。  
> 关联文档：`AI职业导航项目方案.md`、`产品需求文档_PRD.md`、`接口设计文档.md`。  
> 说明：本文中的 ID、Key、URL 均为平台创建后填写项，不能提交到公开仓库。

## 1. 总体配置原则

CareerMate 在百宝箱中采用“Prompt 主智能体 + 工作流核心业务 + 知识库分库 + 基于已有 API 创建插件”的方案。

| 能力 | 百宝箱配置方式 | 项目用途 |
|---|---|---|
| 主智能体 | 通过写 Prompt 创建 | CareerMate 角色、语气、对话入口、侧边助手 |
| 核心业务 | 工作流创建 | 画像采集、职业匹配、路径规划、模拟训练、资源查询 |
| 知识增强 | 知识库/数据仓库 | 岗位能力、学习资源、训练场景、伦理规则 |
| 工具调用 | 基于已有 API 创建插件 | 课程查询、岗位查询、画像读写、进度更新 |
| 外部调用 | 开放平台 API | Next.js 服务端调用智能体与知识库召回 |
| 发布展示 | Web 服务/小程序插件 | 平台发布验证截图 |
| 质量评估 | 命中测试/评测中心 | 知识库与智能体效果评估报告 |

## 3. 应用创建

### 3.1 新建应用

配置项：

- 应用名称：`CareerMate AI 职业导航伙伴`
- 应用简介：面向高校生与职场新人的 AI 职业导航与终身学习伙伴，提供画像采集、职业路径规划、模拟训练和长期记忆管理。
- 应用构建方式：通过写 Prompt 创建主智能体，核心业务通过工作流挂载。
- 模型选择：优先选择稳定、支持较长上下文和工具调用的模型。
- 文件上传：可关闭，初赛主流程不依赖用户上传简历。
- 联网搜索：默认关闭，避免不可控来源；如开启，需在回答中标注来源并用于辅助，不作为正式知识库内容。

截图要求：

- 应用基本信息页。
- 模型配置页。
- 发布状态页。

### 3.2 主智能体角色 Prompt

建议 Prompt：

```text
你是 CareerMate，一个面向高校生与职场新人的 AI 职业导航与终身学习伙伴。

你的目标：
1. 通过自然追问理解用户背景、兴趣、能力、约束和目标岗位。
2. 将长期职业目标拆解为可执行的阶段任务。
3. 用温和、专业、可验证的方式给出建议，避免绝对化判断。
4. 在涉及用户画像、长期计划、能力评分、敏感信息时，先生成更新候选，等待用户确认。
5. 优先引用 CareerMate 的岗位能力库、学习资源库、训练场景库和伦理规则库。
6. 需要查询课程、岗位样例、画像或进度时，调用对应插件工具。

输出规则：
- 面向用户时，先给结论，再给理由和下一步。
- 面向 Web 系统时，按系统要求输出 JSON，不要添加多余解释。
- 不编造真实招聘平台数据，不要求用户提供身份证、手机号、家庭收入等无关隐私。
- AI 建议仅供参考，最终选择由用户决定。

重要约束：
- 目标岗位、能力分、长期计划、敏感信息相关更新必须等待用户确认。
- 如果知识库没有可靠依据，应说明“不确定”，并建议补充信息或查看外部来源。
```

截图要求：

- Prompt 配置页。
- 开场白配置页。
- 知识库/技能挂载页。

## 4. 工作流配置

### 4.1 工作流总览

| 工作流名称 | 触发场景 | 输入 | 输出 |
|---|---|---|---|
| `WF_PROFILE_COLLECT` | 首次画像、聊天后画像更新 | 用户回答、已有画像 | 画像 JSON、更新候选 |
| `WF_CAREER_MATCH` | 仪表盘匹配度解释 | 用户画像、目标岗位、能力分 | 匹配解释、短板、建议 |
| `WF_PLAN_GENERATE` | 生成/重规划职业路径 | 用户画像、目标岗位、时间投入 | 3 年计划 JSON |
| `WF_SIMULATION_TRAIN` | 职场模拟训练 | 场景类型、用户回答、目标能力 | 评分、反馈、更新候选 |
| `WF_RESOURCE_QUERY` | 资源中心/助手推荐 | 岗位、阶段、能力短板 | 课程/岗位/认证/项目资源 |
| `WF_ROLE_DRAFT` | Admin 生成岗位草稿 | 岗位名称、来源摘要、模板约束 | 岗位草稿 JSON |

### 4.2 `WF_PROFILE_COLLECT` 画像采集工作流

节点建议：

1. 开始节点：接收 `user_id`、`conversation_id`、`message`、`current_profile`。
2. 变量节点：标准化用户阶段、目标岗位、时间投入。
3. 分支节点：
   - 信息不足：进入追问生成。
   - 信息足够：进入画像结构化。
4. 文本大模型节点：生成追问或画像更新候选。
5. 伦理规则知识库节点：检查是否涉及敏感信息。
6. 输出节点：返回 `assistant_message` 和 `profile_update_candidate`。

输出 JSON：

```json
{
  "assistant_message": "我先确认一下，你每周大概能投入多少时间？",
  "profile_update_candidate": {
    "type": "preference",
    "field": "weeklyAvailableHours",
    "value": 6,
    "confidence": 0.78,
    "requiresConfirmation": true,
    "reason": "用户表达每周晚上和周末可学习约 6 小时"
  },
  "next_question": "你更喜欢看视频课，还是通过项目练习？"
}
```

截图要求：

- 工作流节点总览。
- 分支节点配置。
- 大模型节点 Prompt。
- 输出 JSON 示例。

### 4.3 `WF_CAREER_MATCH` 职业匹配工作流

节点建议：

1. 开始节点：接收 `user_profile`、`target_role`、`ability_scores`。
2. 知识库节点：召回岗位能力库。
3. 变量节点：接收 Web 端规则评分结果。
4. 文本大模型节点：解释匹配度、短板和建议。
5. 输出节点：结构化解释。

说明：

- 匹配度分数由 Web 端规则算法计算，百宝箱负责解释和建议。
- 解释要说明依据，不做“你不适合某岗位”的绝对判断。

### 4.4 `WF_PLAN_GENERATE` 路径规划工作流

节点建议：

1. 开始节点：接收用户画像、目标岗位、每周可投入时间、当前能力短板。
2. 知识库节点：召回岗位能力库和学习资源库。
3. 文本大模型节点：生成 3 年计划 JSON。
4. 伦理规则知识库节点：检查建议是否过度承诺或不现实。
5. 输出节点：返回可保存 JSON。

输出 JSON 必须包含：

```json
{
  "targetRole": "AI 产品经理",
  "years": [
    {
      "yearIndex": 1,
      "goal": "建立 AI 产品基础能力，完成 2 个作品集项目"
    }
  ],
  "quarters": [
    {
      "quarterIndex": 1,
      "goal": "理解岗位能力模型，完成 AI 产品分析报告"
    }
  ],
  "months": [
    {
      "monthIndex": 1,
      "goal": "理解 AI 产品经理岗位职责",
      "learningTasks": ["学习产品需求文档结构", "拆解 2 个 AI 应用"],
      "practiceOutputs": ["完成一份 AI 工具竞品分析"],
      "evaluationMetrics": ["产出不少于 1500 字", "包含用户场景、核心功能和改进建议"]
    }
  ],
  "assumptions": ["用户每周可投入 6 小时"],
  "riskNotes": ["如果时间投入低于每周 3 小时，需要降低任务密度"]
}
```

### 4.5 `WF_SIMULATION_TRAIN` 模拟训练工作流

训练场景：

| 场景 ID | 名称 | AI 扮演角色 | 用户任务 |
|---|---|---|---|
| `cross_role_communication` | 跨岗位沟通 | 技术负责人/业务方 | 澄清需求、处理冲突、达成共识 |
| `ai_office_task` | AI 辅助办公 | 上级/协作者 | 生成会议纪要、竞品分析、需求文档 |
| `remote_collaboration` | 远程协作 | 项目成员/负责人 | 异步汇报、拆解任务、反馈风险 |

输出 JSON：

```json
{
  "score": 82,
  "strengths": ["表达目标清晰", "能主动澄清约束"],
  "improvements": ["可以补充优先级判断", "风险反馈应更具体"],
  "abilityImpact": {
    "communication": 3,
    "businessUnderstanding": 2,
    "projectPractice": 1
  },
  "profileUpdateCandidate": {
    "field": "abilityScores.communication",
    "value": 72,
    "requiresConfirmation": true,
    "reason": "用户在跨岗位沟通训练中表现出较好的澄清能力"
  }
}
```

### 4.6 `WF_RESOURCE_QUERY` 资源查询工作流

节点建议：

1. 开始节点：接收 `role`、`stage`、`ability_gap`、`resource_type`。
2. 插件节点：调用课程查询、岗位查询或进度查询工具。
3. 知识库节点：补充学习资源库。
4. 输出节点：返回资源列表。

资源要求：

- 不返回非授权爬取招聘数据。
- 外链资源只提供标题、来源、链接和推荐理由，不复制大段正文。

### 4.7 `WF_ROLE_DRAFT` 岗位草稿工作流

用途：管理员输入新岗位名称后，AI 生成岗位模板草稿，等待人工审核。

输出字段：

- 岗位名称。
- 岗位类别。
- 能力维度与权重。
- 入门要求。
- 3 年路径模板。
- 月度任务模板。
- 实践项目。
- 推荐资源。
- 模拟训练场景。
- 来源引用。
- 风险说明。

约束：

- 草稿不能直接进入正式知识库。
- 来源不清或结构不完整的草稿必须拒绝。

## 6. 插件/MCP 工具配置

### 6.1 插件总体策略

使用“我的 → 插件 → 新建插件 → 基于已有服务创建”。插件创建后必须调试通过并发布，才能在应用工作流中使用。插件仅能在同一空间内的应用调用。

建议建立一个插件：

- 插件名称：`CareerMate 工具插件`
- 插件描述：为 CareerMate 提供课程查询、岗位样例查询、用户画像读写和进度更新能力。
- 正式环境 URL：待部署后填写，例如 `https://careermate.example.com/api/mcp`
- 测试环境 URL：本地穿透或测试部署地址，调试阶段填写。
- 认证方式：Bearer Token 或自定义 Header，避免开放匿名写接口。

### 6.2 工具清单

| 工具名 | 对应接口 | 方法 | 用途 |
|---|---|---|---|
| `query_courses` | `/api/mcp/courses/query` | POST | 按岗位、阶段、能力短板返回课程资源 |
| `query_jobs` | `/api/mcp/jobs/query` | POST | 返回脱敏岗位样例 |
| `read_profile` | `/api/mcp/profile/read` | POST | 读取用户画像摘要 |
| `update_profile_candidate` | `/api/mcp/profile/update-candidate` | POST | 写入画像更新候选 |
| `update_progress` | `/api/mcp/progress/update` | POST | 更新学习任务、训练结果和成长日志 |

### 6.3 工具调试要求

每个工具调试通过后截图：

- 工具基础信息。
- 输入参数配置。
- 输出参数配置。
- 调试请求。
- 调试成功结果。
- 插件发布状态。
- 工作流中引用插件节点的截图。

### 6.4 插件调用 Prompt 示例

```text
当用户询问具体课程、岗位样例、学习资源时，优先调用 {query_courses} 或 {query_jobs}。
当你需要读取用户当前画像再给出建议时，调用 {read_profile}。
当对话中出现新的目标岗位、能力变化或长期计划变化时，不要直接改画像，调用 {update_profile_candidate} 生成待确认候选。
当用户完成任务或训练时，调用 {update_progress} 记录进度。
```
