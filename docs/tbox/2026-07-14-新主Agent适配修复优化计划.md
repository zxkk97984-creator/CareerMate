# CareerMate 新主 Agent 适配修复优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Do not skip failing-test, focused verification, or checkpoint steps.

**Goal:** 将 CareerMate 改造成“一个已发布的百宝箱主 Agent 统一编排所有 AI 语义生成，CareerMate 服务端负责安全上下文、协议归一化、Schema 校验、候选持久化、用户确认和明确降级”的稳定架构。

**Architecture:** 浏览器只调用 CareerMate 的 Next.js API；Next.js 只调用一个已发布的主 Agent `agent_id`。主 Agent 在百宝箱内部选择知识库和子工作流，并通过文本或结构化结果返回；CareerMate 统一归一化 SSE，在流结束后解析结构化结果，通过能力专属 Zod Schema 后才创建画像、计划、探索或模拟报告候选。任何失败都保留可展示文本，`api → manual → mock` 降级必须通过执行元数据明确呈现。

**Tech Stack:** Next.js 16、React 19、TypeScript 5.9、Zod 3、Prisma 6、SQLite、Vitest、Playwright、百宝箱 OpenAPI SSE。

## 0. 已批准的设计决策

本计划以《CareerMate_百宝箱智能体现状与Codex适配说明.md》和 2026-07-14 代码审计为事实基线。

### 0.1 选择的方案

采用“主 Agent 单一编排入口 + CareerMate 可信执行边界”：

```text
CareerMate 前端
  → Next.js API（认证、安全上下文、稳定 user_id）
  → 已发布主 Agent
      → 技能评估Agent
      → 画像匹配
      → 职业规划Agent
      → 学习路线Agent
      → 模拟面试Agent
      → 简历优化Agent
      → 已挂载知识库/联网能力
  ← 文本、结构化结果、引用、conversation_id
  → CareerMate 归一化、Zod 校验、候选落库、用户确认
```

### 0.2 不采用的方案

1. **继续保留“主回答一次 + 本地正则再判断 + 第二次 Agent/本地模板生成卡片”**：会让回答与卡片来自两个判断源，结果可能矛盾。
2. **让 Agent 直接写 CareerMate 正式数据库**：会绕过权限、用户确认、并发控制和审计边界。
3. **一次性同时接入 Agent、MCP、长期记忆和所有外部数据源**：故障面过大，无法定位协议问题。

### 0.3 必须保留的本地职责

- 用户认证、稳定 `user_id`、跨用户数据隔离。
- 画像、计划、长期记忆和能力证据的用户确认。
- Prisma 事务、幂等、并发控制、版本管理。
- Zod 白名单校验和结构化卡片创建。
- `api → manual → mock` 降级及真实执行来源展示。
- 明确、可解释的确定性计算；但不得把本地模板冒充 Agent 生成结果。

### 0.4 完成定义

只有下列条件全部满足，才能声称适配完成：

- 所有生产 AI 语义生成都通过一个已发布主 Agent 的 `agent_id`。
- 主聊天不再用本地关键词检索作为默认编排器。
- 主聊天卡片只来自本次 Agent 响应中通过 Zod 的结构化结果。
- Markdown 回答永远不会因 JSON 解析失败而丢失。
- `conversation_id` 在主聊天、引导对话、模拟训练中正确保存和复用。
- SSE 支持跨 chunk、CRLF/LF、JSON/纯文本、未知事件、变量结果及重复输出。
- 结构不合格时不落库、不创建业务引用卡片，并记录 `SCHEMA_MISMATCH`。
- 降级结果在 UI 和持久化元数据中可识别，不能伪装成真实 API 结果。
- lint、类型检查、单元测试、迁移测试、构建和 E2E 全部通过。

- [ ] **Step 3: 实现最小累积器**

`src/lib/tbox/result.ts` 必须实现以下公开接口：

```ts
import type { NormalizedAiEvent, NormalizedAssistantResult } from "./types";

export interface AssistantResultAccumulator {
  consume(event: NormalizedAiEvent): string;
  finalize(): NormalizedAssistantResult;
}

export function createAssistantResultAccumulator(): AssistantResultAccumulator {
  let text = "";
  let structured: unknown;
  let conversationId: string | undefined;
  const citations: unknown[] = [];
  const warnings: string[] = [];
  let lastFinal = "";

  return {
    consume(event) {
      if (event.type === "conversation") conversationId = event.conversationId;
      if (event.type === "structured_result") structured = event.payload;
      if (event.type === "citation") citations.push(event.payload);
      if (event.type === "warning" && !warnings.includes(event.code)) warnings.push(event.code);
      if (event.type === "text_delta") {
        text += event.text;
        return event.text;
      }
      if (event.type !== "text_final" || !event.text.trim()) return "";

      const finalText = event.text.trim();
      if (finalText === lastFinal || finalText === text) {
        if (!warnings.includes("DUPLICATE_RESPONSE")) warnings.push("DUPLICATE_RESPONSE");
        lastFinal = finalText;
        return "";
      }
      if (finalText.startsWith(text)) {
        const suffix = finalText.slice(text.length);
        text = finalText;
        lastFinal = finalText;
        return suffix;
      }
      if (text.startsWith(finalText)) {
        if (!warnings.includes("DUPLICATE_RESPONSE")) warnings.push("DUPLICATE_RESPONSE");
        lastFinal = finalText;
        return "";
      }

      const addition = text ? `\n\n${finalText}` : finalText;
      text += addition;
      lastFinal = finalText;
      return addition;
    },
```
