# CareerMate AI 职业导航与终身学习伙伴系统总计划

## 1. 项目定位

CareerMate 是一个基于蚂蚁百宝箱企业版的 AI 职业导航与终身学习伙伴系统，面向高校生与职场新人，帮助用户从个人背景、兴趣、能力和目标出发，形成可执行、可追踪、可动态调整的职业发展路径。

本项目不是一次性职业测评工具，也不是单纯的学习资料推荐平台，而是一个长期陪伴型 AI 职业成长系统。它需要体现赛题要求的完整闭环：

- 感知：通过对话采集用户状态、目标、能力、偏好和学习进度。
- 认知：结合职业知识库、岗位趋势、学习资源和用户画像进行分析。
- 决策：生成职业方向推荐、岗位匹配度和 3 年成长路径。
- 生成：输出月度行动计划、学习任务、实践任务和模拟训练反馈。
- 执行：通过 MCP/API 工具查询课程、岗位、画像和进度。
- 反馈：根据用户聊天、任务完成和训练表现持续修正画像与路径。

项目名称：CareerMate  
AI 助手名称：CareerMate  
助手形象：轻二次元职场伙伴，首期做静态状态切换。

## 2. 赛题目标与评分导向

根据赛题和附件一评分标准，本项目应优先服务以下评分点：

- 项目创意：突出长期陪伴、动态画像、路径可执行、AI 伦理和多职业扩展。
- 实施方案：目标清晰、阶段合理、难点明确、资源配置可落地。
- 技术实现与交付：完成 Web 原型、百宝箱智能体、知识库、MCP/API、可视化看板、多端发布验证。
- 项目展示：PPT、演示视频、技术说明、伦理说明、测试反馈、平台配置截图完整。

核心策略：

> 用 3 个核心岗位把主流程做深，用可扩展岗位模板证明系统能适配更多职业，用百宝箱完成智能体、知识库、MCP 和多端发布验证。

## 3. 用户范围与演示账号

系统采用真实多用户设计，但不做复杂企业级账号体系。首期使用本地账号登录，SQLite 保存不同用户的数据，实现用户画像、路径、进度和记忆的隔离。

账号类型：

- 普通用户：使用职业规划、路径生成、训练和记忆权限功能。
- 管理员：审核 AI 生成的岗位草稿，维护职业知识库扩展。

准备 5 个演示用户，采用“3 个学生主线 + 2 个职场/转岗对比”的方式。

建议演示用户：

| 用户 | 身份 | 背景 | 目标/场景 | 演示价值 |
| --- | --- | --- | --- | --- |
| 小林 | 大三学生 | 数字媒体技术，会基础办公，对 AI 产品感兴趣 | AI 产品经理 | 主演示用户，完整跑通画像、路径、训练、记忆 |
| 小周 | 大二学生 | 统计/数学基础较好，想找数据方向实习 | 数据分析师 | 展示数据路线与能力雷达差异 |
| 小陈 | 新闻传播学生 | 会内容创作，常用 AIGC 工具 | AIGC 内容运营 | 展示非技术学生进入 AI 岗位的路径 |
| 阿敏 | 职场新人 | 运营岗位 1 年，时间少，想转 AI 产品 | 时间受限转岗 | 展示同目标下因时间约束生成不同计划 |
| 宇航 | 职场新人 | 做过新媒体，原本想做数据分析，后续调整方向 | 目标调整 | 展示系统支持目标变化和路径重规划 |

## 4. 职业知识库策略

首期不追求覆盖所有职业，而是采用：

> 3 个核心岗位深做 + 统一岗位导入模板 + 实时查询/API 作为补充。

首期核心岗位：

- AI 产品经理
- 数据分析师
- AIGC 内容运营

这 3 个岗位分别代表：

- 产品/业务/沟通型路径
- 数据/分析/决策型路径
- 内容/运营/增长型路径

后期可以通过合规数据、授权 API、人工整理数据或 AI 辅助生成岗位草稿扩展更多职业。

### 4.1 岗位模板

每个岗位都用统一结构保存，避免写死岗位逻辑。

岗位模板字段：

- 岗位名称
- 岗位类别
- 适合人群
- 入门要求
- 核心工作内容
- 核心能力维度
- 能力权重
- 3 年成长路径
- 季度里程碑
- 月度任务模板
- 实践项目
- 推荐课程/资源
- 模拟训练场景
- 面试/求职准备
- 评估规则
- 参考来源

### 4.2 外部资源使用原则

roadmap.sh、公开行业报告、课程平台目录等可以作为学习路线组织方式和外链参考，但不直接复制其图片、JSON、PDF 或原文内容。

推荐写法：

> 系统参考 roadmap.sh 等公开学习路线平台的路径组织方式，结合高校生与职场新人场景，重新构建适合本项目的岗位能力模型、阶段目标和实践任务。项目不直接复制第三方路线图图片、文本或数据文件，仅将其作为外部参考链接和学习资源入口。

## 5. 核心功能规划

### 5.1 对话式用户画像

用户首次登录后进入 CareerMate 对话式画像采集流程。AI 不要求用户一次性填完长表单，而是通过连续追问建立初始画像。

画像采集内容：

- 当前身份：高校生、职场新人、转岗用户等。
- 专业/行业背景。
- 过往经历：课程、实习、项目、社团、工作经验。
- 兴趣偏好。
- 目标岗位或目标方向。
- 每周可投入时间。
- 学习偏好：项目驱动、课程学习、实战任务、面试导向等。
- 当前技能水平。
- 风险偏好和约束：时间少、基础弱、不想高强度刷题等。

后续任意聊天都触发画像更新候选。AI 会根据用户新表达的信息持续修正画像。

更新策略：

- 普通偏好可自动更新，例如“更喜欢项目驱动学习”。
- 目标岗位、能力分、长期计划、隐私相关内容需要用户确认。
- 所有重要更新都保存为画像更新候选，用户确认后正式写入。

### 5.2 动态职业画像与雷达图

能力雷达图采用 6 个通用能力维度：

- AI 理解与工具应用
- 岗位专业基础
- 数据分析能力
- 业务/产品理解
- 沟通协作表达
- 项目实践与作品沉淀

不同岗位采用不同权重。

示例：

- AI 产品经理：业务/产品理解、沟通协作、AI 工具应用权重更高。
- 数据分析师：数据分析、岗位专业基础、项目实践权重更高。
- AIGC 内容运营：AI 工具应用、内容表达、业务增长意识权重更高。

匹配度采用“规则评分 + AI 解释”：

- 规则算法输出能力分和岗位匹配度。
- 百宝箱智能体生成可读解释、短板分析和下一步建议。

### 5.3 3 年职业路径与月度计划

系统为每个用户生成 3 年主计划。

路径结构：

- 每年总目标
- 每季度里程碑
- 36 个月行动计划
- 当前月重点任务

每个月计划包含：

- 月目标
- 学习任务
- 实践产出
- 评估指标

示例结构：

```text
第 1 年目标：建立 AI 产品经理基础能力，完成 2 个 AI 产品分析和 1 个原型项目。

Q1：理解 AI 产品与产品经理基础
Q2：完成竞品分析和用户研究训练
Q3：完成 AI 应用原型
Q4：形成作品集并准备实习

第 1 个月：
- 月目标：理解 AI 产品经理的岗位职责和基础能力模型
- 学习任务：学习 AI 产品基础、需求分析、用户画像
- 实践产出：完成 1 份 AI 产品竞品分析
- 评估指标：能清楚说明目标用户、核心需求、功能拆解和改进建议
```

当用户目标、时间投入、训练表现或能力分变化后，可以触发路径重规划。

### 5.4 职场模拟训练

首期提供 3 个互动式职场训练模块，共用同一训练框架。

训练模块：

- 跨岗位沟通：AI 扮演技术负责人或业务方，训练需求表达、约束澄清和冲突沟通。
- AI 辅助办公：用户完成会议纪要、竞品分析、需求文档、复盘报告等任务。
- 远程协作：训练异步沟通、任务拆解、进度同步和风险反馈。

每次训练输出：

- 场景得分
- 关键表现
- 改进建议
- 对能力维度的影响建议
- 是否生成画像更新候选

训练结果不会直接修改能力分，而是生成画像更新候选，经用户确认后写入。

### 5.5 资源中心与 MCP/API 对接

首期做 4 个核心工具：

- 课程查询：按岗位、阶段、能力短板返回课程资源。
- 岗位查询：按目标岗位、城市、能力标签返回脱敏岗位样例。
- 画像读写：读取用户画像，写入用户确认后的画像更新。
- 进度更新：更新学习任务、训练结果和成长日志。

MCP/API 只接入合规数据源。

真实招聘平台 API 若无授权，不作为初赛依赖。不爬取 BOSS、智联、前程无忧等平台的非授权数据。

结合已下载的百宝箱企业版文档目录和可读的《API接入概述》，百宝箱开放 API 当前按邀测/白名单方式申请，项目不能默认一开始就能拿到完整 OpenAPI 权限。因此首期实现要分两层：

- 平台交付层：在百宝箱企业版内完成智能体、工作流、知识库、Web 服务投放和多端发布验证截图。
- Web 集成层：Next.js 服务端预留百宝箱 API 代理能力，拿到 API-Key、应用 appid 和白名单后接入真实调用。
- 开发降级层：接口未开通时，本地 Web 可使用手工导入的百宝箱输出样例或本地测试数据调试页面，但提交和演示材料要明确区分“平台真实配置”和“本地开发占位数据”，不把占位数据伪装成真实百宝箱调用。

比赛阶段采用：

- 人工整理公开信息
- 脱敏改写
- 自建模拟课程/岗位/认证数据
- 标准 API/MCP 工具调用演示

### 5.6 长期记忆与用户权限中心

系统设计 Career Memory Profile，用于支持长期陪伴。

每个用户拥有独立记忆，不使用全局共享文件。

记忆内容包括：

- 用户长期目标
- 学习偏好
- 时间约束
- 最近困难
- 完成过的任务
- 模拟训练反馈
- 已确认的画像变化

用户权限中心支持：

- 查看画像和长期记忆
- 编辑画像字段
- 删除单条记忆
- 导出个人数据
- 关闭长期记忆
- 清空账号数据

这样可以体现 AI 伦理、隐私保护和用户自主控制。

### 5.7 Admin 岗位草稿审核

岗位扩展采用：

> AI 辅助生成岗位草稿 → 结构化校验 → 来源引用 → 管理员审核 → 进入正式知识库。

管理员审核页首期纳入实现范围。

管理员可以：

- 查看 AI 生成的岗位草稿。
- 检查岗位能力、权重、路径、资源和来源。
- 修改不合理字段。
- 点击通过后写入正式职业知识库。
- 拒绝质量不合格或来源不清的草稿。

这个功能用于展示知识库可扩展能力，同时避免 AI 自动生成内容直接污染正式知识库。

## 6. 蚂蚁百宝箱平台设计

### 6.1 百宝箱职责

百宝箱企业版作为 AI 能力中枢，负责：

- 主智能体配置
- 角色提示词
- 大模型调用
- 职业知识库检索
- 工作流编排
- MCP/API 工具调用
- Web 服务发布
- 小程序发布验证

已下载文档目录显示，百宝箱企业版至少覆盖以下与本项目强相关的模块：

- 应用：新建应用、调试应用、发布应用、以 Web 服务形式对外投放、以插件形式上架至支付宝/微信小程序。
- 开放平台：API 接入概述、智能体调用、会话管理、文件管理、知识库调用、运营数据。
- 知识库：知识库创建、添加数据、使用知识库、命中测试、数据仓库、Markdown 使用指南、结构化知识库模板。
- 工作流/插件：工作流概述、HTTP 请求节点、知识库节点、插件节点、MCP 插件、基于已有 API 创建插件、创建端插件/流式插件。
- 评测中心：评测智能体、准备评测数据集、准备评测指标。

### 6.2 智能体架构

采用“主智能体 + 工作流”架构。

结合百宝箱的 3 种应用构建方式，CareerMate 按用途分工：

| 百宝箱构建方式 | CareerMate 用法 |
|---|---|
| 工作流创建 | 主力方式。画像采集、职业匹配、路径规划、模拟训练都走工作流，使用大模型节点、知识库节点、HTTP 请求节点、插件节点、分支/变量/意图识别节点。 |
| 通过写 Prompt 创建 | 用于 CareerMate 侧边 AI 助手的角色设定、陪跑闲聊、轻量问答，并在 Prompt 中引导调用知识库和插件。 |
| AI 自然语言构建 | 不承载核心逻辑，仅用于快速生成 H5/小程序原型或演示型页面。 |

主智能体：CareerMate 职业成长伙伴。

工作流节点：

- 用户画像提取
- 画像更新候选生成
- 职业匹配分析
- 3 年路径规划
- 月度任务生成
- 职场模拟训练
- 训练评分与反馈
- 资源查询
- 伦理与隐私检查

### 6.3 知识库分库

知识库按用途分库管理：

- 岗位能力库：岗位职责、能力模型、能力权重、职业路径模板。
- 学习资源库：课程、书籍、路线图外链、实践项目。
- 训练场景库：远程协作、AI 辅助办公、跨岗位沟通脚本。
- 伦理规则库：隐私保护、反标签化、推荐解释、用户自主决策规则。

落地细节：

- 数据先上传到百宝箱数据仓库，再关联到不同知识库，便于同一批数据复用。
- 每个知识库独立配置召回策略，包括最大返回数、最小匹配度阈值等。
- 岗位模板和资源模板优先使用 Markdown 或结构化模板，便于后续导入、更新和审核。
- 使用百宝箱自带命中测试验证召回质量，并把测试结果写入知识库构建与评估报告。

分库管理便于后续写“知识库构建方法与效果评估报告”。

### 6.4 百宝箱输出约定

百宝箱输出采用：

- JSON 优先
- 附带用户可读文本解释

前端依赖 JSON 渲染雷达图、路径、月度任务、训练评分和资源列表。

如果百宝箱调用失败或输出不合格：

- 系统提示用户重试。
- 保留用户已输入草稿。
- 不伪造 AI 结果。

### 6.5 官方文档适配后的落地方式

根据《API接入概述》和《百宝箱平台适配分析》中的接口口径，百宝箱开放 API 的接入顺序应调整为：

1. 先在百宝箱企业版创建并发布 CareerMate 应用。
2. 在开放平台申请/创建对应空间租户的 API-Key，并确认应用 appid、租户、调用权限和白名单状态。
3. 通过开放平台能力调用智能体应用、知识库、文件管理等接口。
4. Next.js 只在服务端保存 token、API-Key、appid 等配置，前端不直接接触百宝箱密钥。

已整理出的关键 API 口径：

- 智能体对话：`POST https://o.tbox.cn/openapi/v1/chat/create`
- 鉴权方式：`Authorization: Bearer {API-Key}`
- 对话请求体核心字段：`agent_id`、`question`、`user_id`、`conversation_id`、`stream`
- 流式能力：支持 SSE 流式和非流式；WebSocket 口径为 `wss://o.tbox.cn/ws/chat`
- 超时约束：流式两次事件间隔 90s 超时，非流式总耗时 90s
- 应用调用条件：应用发布后即可通过 API 调用，不要求先上架到某个渠道
- 知识库召回：`POST https://api.tbox.cn/api/datasets/retrieve`
- 知识库请求体核心字段：`query`、`dataset_id`、`limit`

以上接口字段以最终开通账号后的控制台文档为准，但已经足够指导 Next.js 适配层设计。

因此本项目的百宝箱主链路要按“先平台可运行，再 Web 接入”的顺序推进：

- 百宝箱内先完成主智能体、工作流、知识库和发布配置，保证平台侧可以独立演示。
- Web 端通过服务端代理调用百宝箱对话型智能体，要求输出 JSON + 文本解释。
- 聊天页优先对接 SSE 流式输出；若后续需要更强实时性，再接 WebSocket；若暂未开通，则保留普通非流式调用。
- 文档中提到内容生成型应用暂不支持开放 API，因此 3 年职业路径、训练反馈、岗位草稿生成都应通过“对话型智能体 + 严格 JSON 输出约束”完成，而不是依赖单独的内容生成应用接口。

### 6.6 百宝箱工作流建议

CareerMate 在百宝箱中建议配置为一个主智能体和多个工作流：

- 画像采集工作流：用户输入 → Query 改写/变量节点 → 文本大模型节点 → 画像更新候选 JSON。
- 职业匹配工作流：读取画像 → 知识库节点召回岗位能力模型 → 规则分数由 Web 端计算 → 大模型生成解释。
- 路径规划工作流：读取目标岗位和能力短板 → 知识库召回路径模板和资源 → 输出 3 年计划 JSON。
- 模拟训练工作流：场景变量 → AI 扮演职场角色 → 用户多轮回答 → 评分与画像更新候选。
- 资源查询工作流：通过 HTTP 请求节点/插件/MCP 调用课程、岗位样例、进度更新等内部接口。

MCP/API 工具优先选择百宝箱“基于已有 API 创建插件”路径：

- 课程查询、岗位查询、画像读写、进度更新这 4 个工具先在 Next.js 暴露内部 API。
- 再把这些内部 API 包装成百宝箱插件/MCP 工具，工作量低于自部署 MCP Server。
- 插件在百宝箱工作流的“插件节点”中使用，或挂到大模型节点的“添加技能”里。
- Prompt 中用 `{插件名}` 等方式引导模型在合适场景调用工具。
- 只有当工具逻辑复杂到无法通过已有 API 包装时，再考虑 IDE 云开发或自部署 FastMCP Server。

如果官方 MCP 插件流程权限不足，则退而求其次使用 HTTP 请求节点调用 Next.js 暴露的合规内部 API。

## 8. 数据模型规划

## 9. API 与服务端规划

Next.js 服务端负责封装内部 API，前端不直接调用百宝箱 token。

百宝箱适配层需要预留以下配置项和能力：

- `TBOX_API_KEY`：开放平台 API-Key 或 token。
- `TBOX_APP_ID`：百宝箱应用 appid。
- `TBOX_AGENT_ID`：CareerMate 对话型智能体 ID。
- `TBOX_DATASET_IDS`：岗位能力库、学习资源库、训练场景库、伦理规则库对应的知识库/数据集 ID。
- `TBOX_BASE_URL`：开放平台 API 基础地址，等完整接口文档确认。
- `TBOX_CHAT_ENDPOINT`：默认 `https://o.tbox.cn/openapi/v1/chat/create`。
- `TBOX_RETRIEVE_ENDPOINT`：默认 `https://api.tbox.cn/api/datasets/retrieve`。
- `TBOX_WS_URL`：默认 `wss://o.tbox.cn/ws/chat`，作为后续 WebSocket 方案预留。
- `TBOX_TENANT_ID`：如接口要求空间租户标识，则服务端统一维护。
- `TBOX_MODE`：`api`、`manual`、`mock` 三种模式，分别用于真实 API 调用、手工导入百宝箱输出、开发期本地调试。
- `TBOX_STREAM_TIMEOUT_MS`：按平台 90s 超时约束设置前后端等待和重试策略。
- 用户映射：本地 `User.id` 映射为百宝箱调用中的 `userId` 或业务用户标识，避免不同用户会话和记忆串号。

当前已创建的百宝箱资源：

- 百宝箱空间名称：外包。
- 应用名称：CareerMate职业导航。
- 应用类型：对话型智能体。
- 应用发布状态：已发布，版本 `1.0`。
- `TBOX_APP_ID`：`202607APRX0a19730150`。
- Web 服务链接：`https://b.tbox.cn/inc/share/202607APRX0a19730150?platform=WebService`。
- API-Key：已创建“智能体调用”令牌，完整 Key 不写入文档，只保存到服务端环境变量；截图中已暴露的旧令牌建议删除重建。
- `TBOX_AGENT_ID`：已确认 `202607APRX0a19730150`。

内部 API 类型：

- 认证 API：登录、注册、退出、获取当前用户。
- 画像 API：读取画像、更新画像、确认更新候选。
- 职业路径 API：生成计划、读取计划、更新任务状态。

百宝箱调用失败处理：

- 提示重试。
- 记录错误信息。

- 不用本地假结果冒充百宝箱结果。

## 11. AI 伦理与隐私设计

伦理设计不能只写在文档里，应体现在功能里。

- 用户可以删除单条记忆。

- 不采集与职业规划无关的敏感信息。
- 模拟招聘数据不包含姓名、手机号、聊天记录等个人信息。

- AI 生成岗位草稿需要管理员审核。

## 17. 风险与取舍

### 17.1 不做真实招聘网站爬虫

原因：

- 合规风险高。
- 可能违反平台用户协议。
- 招聘数据中可能包含个人信息或平台商业数据。
- 赛题要求的是 API 对接演示，不是爬虫采集。

替代方案：

- 自建脱敏模拟招聘数据。
- 采用标准 API/MCP 工具形式演示。
- 后续在获得招聘平台授权后替换真实接口。

### 17.2 不做完整原生小程序

原因：

- Web 是必选，小程序是可选。
- 单独开发小程序会占用大量时间。
- 百宝箱平台发布验证已经能体现多端能力。

替代方案：

- Web 端做完整体验。
- 百宝箱完成 Web 服务和小程序发布验证截图。

### 17.3 不做全行业职业百科

原因：

- 职业过多会导致每个岗位内容浅。
- 难以保证路径质量。
- 演示重点会分散。

替代方案：

- 首期深做 3 个岗位。
- 通过岗位模板、AI 草稿和管理员审核证明可扩展。

### 17.4 百宝箱 OpenAPI 权限不确定

原因：

- 《API接入概述》显示开放 API 当前支持邀测方式申请，需要联系官方技术支持申请白名单试用。
- 智能体调用、知识库召回、SSE/WebSocket 等关键口径已经初步明确，`agent_id` 已确认，`dataset_id` 和 API 白名单权限仍需以开通后的控制台为准。
- 如果等到最后才接入 API，容易影响 Web 主链路演示。

取舍：
