# CareerMate 全站温暖陪伴视觉统一设计

## 1. 设计目标

以当前聊天首页为唯一视觉母版，将登录、画像引导、成长概览、职业路径、模拟训练、资源中心、记忆权限和 Admin 统一到同一产品系统中。此次改造是现有项目的增量升级，不重写路由、接口、Prisma 模型、AI 规则或业务状态。

完成后，用户从聊天页进入任意功能页时，应感到仍在同一个 CareerMate 中，而不是跳进旧后台系统。

## 2. 已确认方案

采用“共享设计系统 + 共享应用外壳 + 逐页迁移”的方案：

- 保留聊天首页现有紫蓝渐变、柔和画布、轻卡片和陪伴式语气。
- 提炼设计令牌与通用组件，不在每个页面复制聊天页 CSS。
- 将 1000 多行的 `workspace.tsx` 拆成数据控制器、共享外壳和独立业务视图。
- 登录页使用同源的独立认证布局，不强行显示登录后的侧栏。
- 画像引导使用同源的沉浸式对话布局，不改回传统长表单。
- 每迁移一个页面就保持该页面业务流程可用，并运行对应测试。

不采用以下方案：

- 只把旧页面的黑色按钮改成紫色：最快，但仍保留两套布局和重复组件。
- 重写整个前端：风险高，会破坏已经验证的聊天、画像、计划和训练流程。

## 3. 视觉语言

### 3.1 色彩

- 页面画布：`#F7F6FF`
- 卡片表面：`#FFFFFF`
- 柔和紫表面：`#EEE9FF`
- 品牌主色：`#7568E8`
- 主色悬停和正文链接：`#5F51D8`
- 渐变辅助蓝：`#7AA8F8`
- 主文字：`#27243A`
- 次级文字：`#747086`
- 弱提示文字：使用比现有 `#A9A6BB` 更深的可读颜色
- 边框：`rgba(117, 104, 232, 0.14)`
- 强边框：`rgba(117, 104, 232, 0.22)`
- 成功、信息、警告、危险状态分别定义前景色和浅背景色，不直接散落硬编码值

### 3.2 圆角、阴影和间距

- 小圆角：8px
- 控件圆角：12px
- 卡片圆角：16px
- 主要容器圆角：20px
- 胶囊圆角：999px
- 卡片只使用轻阴影；抽屉、浮层使用更明显但柔和的悬浮阴影
- 统一使用 4、8、12、16、20、24、32、40、48、64 的间距序列

### 3.3 字体和动效

- 英文优先使用 `var(--font-geist-sans)`。
- 中文后备字体明确为 `PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`。
- 普通反馈 120—150ms，抽屉 250ms。
- 支持 `prefers-reduced-motion`，关闭不必要的平滑滚动、脉冲和位移动画。

## 4. 信息架构与共享外壳

### 4.1 登录后桌面布局

- 左侧固定 280px 产品侧栏。
- 侧栏顶部统一展示 CM 渐变图标和 CareerMate 品牌。
- 聊天页顶部操作是“新对话”，中部是会话历史。
- 其他业务页顶部操作是“返回 AI 对话”，中部用于当前模块说明或保持轻量留白。
- 底部统一展示成长概览、职业路径、模拟训练、资源中心、记忆权限和用户区。
- 当前页面使用浅紫背景、主色图标和 `aria-current="page"`，不再使用黑色实心导航项。
- Admin 只对管理员显示，并与普通用户功能入口分组。

### 4.2 内容页布局

- 主内容最大宽度 1180px，居中显示。
- 页面头部统一包含图标、标题、一句说明、必要的主操作和 AI 运行状态。
- 页面正文使用 16—20px 圆角卡片、低对比紫色边框和轻阴影。
- 信息密度根据任务调整，不把所有页面强行做成聊天空状态。

### 4.3 移动端

- 768px 以下，侧栏变成左侧抽屉。
- 顶部显示品牌、当前页标题和菜单按钮。
- 点击遮罩、关闭按钮或 Escape 均可关闭抽屉；关闭后焦点返回菜单按钮。
- 卡片单列展示，页面左右内边距 12—16px。
- 按钮和输入框触控高度至少 44px，不出现横向滚动。

## 5. 页面设计

### 5.1 登录与注册

- 使用柔和紫蓝背景和低透明渐变光斑。
- 桌面端左侧展示品牌承诺、三个核心能力和隐私提示；右侧为白色 20px 圆角认证卡。
- 移动端收起营销说明，优先显示品牌与认证卡。
- 保留登录/注册切换、账号、昵称、密码、加载、错误和异常响应恢复。
- 使用真正的 `<form>`，支持 Enter 提交。
- 登录成功无 `nextPath` 时默认进入 `/`，不再回退 `/dashboard`。
- 演示账号不再默认伪装成真实输入，改为“填入演示账号”辅助操作或折叠说明。

### 5.2 画像引导

- 使用品牌页头、居中对话区和右侧/底部“画像完整度”摘要。
- 保留多轮对话、恢复历史、用户输入失败恢复和 AI 运行模式。
- 摘要展示阶段、背景、目标职业、时间、偏好、经历和约束。
- 完整度达到 80% 后才激活主按钮；确认前不修改正式画像。

### 5.3 成长概览

- 页面头部显示问候语、目标职业、专业、每周投入和 AI 状态。
- 第一行是岗位匹配度、本周任务、待确认画像三个指标卡。
- 第二行是能力雷达和本周行动卡；任务状态必须清晰可扫读。
- 第三行是匹配说明、薄弱能力和近期成长记录。
- “重新生成计划”需要加载状态和明确风险提示，不能无反馈覆盖计划。

### 5.4 职业路径

- 顶部显示当前职业、计划版本、生成来源和 AI 模式。
- 待确认新版本继续复用 `PlanSummaryCard`，清楚显示新旧差异和“确认新版本”。
- 当前阶段优先呈现本周行动、90 天目标和 12 个月里程碑。
- 3 年、季度和 36 个月完整时间线放入可展开区域，降低首屏信息压力。
- 任务状态更新、首次生成、重规划、错误和降级原因全部保留。

### 5.5 模拟训练

- 左侧为三张训练场景卡，右侧使用聊天气泡式训练区。
- 显示 0/6 轮进度和“至少 3 轮后可评分”的明确说明。
- 活跃训练期间禁止重复开始或切换场景。
- 完成后展示得分、反馈和“已生成待确认画像候选”，不能暗示画像已经自动生效。
- 最近五次训练使用轻量历史列表。

### 5.6 资源中心

- 顶部使用筛选条：目标职业、能力方向、资源类型。
- 薄弱能力显示为推荐筛选标签。
- 资源卡展示标题、类型、说明和真实来源；无链接时不得伪造链接。
- 明确说明当前正式资源库只覆盖首批精品职业，避免误导。

### 5.7 记忆权限与隐私

- 使用“画像候选 / 长期记忆 / 数据隐私”三个清晰分区或页内标签。
- 画像候选卡复用聊天中的候选视觉和确认语义。
- 长期记忆提供开关、创建、编辑、删除；编辑改用站内弹窗，不使用 `window.prompt`。
- 数据导出为普通操作；清空数据放在独立危险区域，要求输入 `CLEAR_MY_DATA` 并二次确认。
- 清空完成后重新进入画像引导。

### 5.8 Admin

- 使用相同外壳，但显示管理员标识和独立导航分组。
- 普通用户访问 `/admin` 时在服务端跳转，不渲染空管理页。
- 岗位草稿生成、结构校验、编辑、通过、拒绝和正式岗位库全部保留。
- 编辑和拒绝使用站内弹窗；异常旧数据不能因 `JSON.parse` 让整页崩溃。

## 6. 共享组件边界

建议建立：

- `AppShell`：桌面/移动端布局和抽屉状态
- `ProductSidebar`：品牌、导航、用户、退出登录和可插槽的顶部/中部区域
- `PageHeader`：标题、说明、图标、操作和状态槽
- `SurfaceCard`：统一表面、边框、圆角和卡片头
- `Button`：primary、secondary、ghost、danger、icon
- `Field`：input、select、textarea 的标签、说明和错误
- `StatusBadge`、`InlineAlert`、`EmptyState`、`Skeleton`
- `ConfirmDialog`：删除、清空、拒绝等确认动作

业务视图只能组合这些基础组件，不再定义自己的黑色 Button、Slate Panel 或第二套色板。

## 7. 保持不变的业务边界

- 不修改 API 路径和响应结构。
- 不修改 Prisma schema、数据库迁移和 seed。
- 不修改画像必须确认后生效的规则。
- 不修改计划新版本确认和旧版本保留规则。
- 不修改模拟训练 3—6 轮和候选生成规则。
- 不修改百宝箱真实/辅助模式判断和来源标注。
- 不引入新的前端框架或 UI 框架；继续使用 Next.js、React、Tailwind 4、CSS variables 和 Lucide。
- 不运行 `npm audit fix --force`。

## 8. 验收标准

- `/`、`/dashboard`、`/path`、`/simulation`、`/resources`、`/memory` 使用同一品牌、侧栏、导航状态和响应式规则。
- `/login` 和 `/onboarding` 视觉同源，但使用适合各自任务的独立布局。
- 普通用户不可看到或打开 Admin；管理员可以正常使用。
- 所有原有业务 E2E 继续通过。
- 1440×900、768×1024、375×812 三种视口无横向溢出、遮挡和重复侧栏。
- 键盘焦点清楚，抽屉支持 Escape，状态不只依靠颜色表达。
- 聊天首页视觉不能因抽取设计系统而退化。
