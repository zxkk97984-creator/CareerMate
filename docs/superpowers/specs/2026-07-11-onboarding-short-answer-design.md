# CareerMate 画像短回答识别修复设计

## 背景与根因

画像引导调用百宝箱 API 生成自然语言回复，但画像的持久化真值来自服务端 `OnboardingDraft`。当前服务端每轮把已校验草稿放进提示词，却不复用百宝箱远端会话 ID；因此模型的当轮理解不会自动成为下一轮可依赖的结构化记忆。

现有规则能从“我的专业是统计学”提取专业，不能从系统刚询问专业后的短回答“数据科学与大数据技术”提取专业。百宝箱当轮会正确回应，但服务端草稿仍缺少 `major`，下一轮又会询问专业。

## 目标

- 在系统正在等待某个画像字段时，安全地理解对应的简短回答。
- 修复现有活跃会话中已经出现在 transcript、但未进入 draft 的专业短回答。
- 继续以服务端 Zod 校验后的草稿作为唯一画像真值。
- 不把任意短句误判为专业，不直接信任百宝箱自然语言回复更新数据库。

## 方案

新增上下文感知的单轮提取函数：

1. 先运行现有显式规则，识别阶段、专业、岗位、时间、偏好、经历和限制。
2. 根据处理本轮前的草稿计算最优先缺失字段。
3. 仅当最优先缺失字段是 `major`、显式规则未提取专业，且用户输入是安全的专业短答时，将其写入 `major`。
4. 专业短答必须是长度受限的单句文本，并排除“不知道”“没有”“随便”等无效回答、问句和明显属于其他画像字段的内容。

新增 transcript 自愈：

1. 在处理新消息前，按顺序回放已有 transcript 中的用户消息。
2. 每条消息都基于当时已重建的草稿进行上下文感知提取。
3. 将重建结果与原有已校验草稿合并，原有明确字段不丢失。
4. 再处理用户当前消息，并把修复后的草稿发给百宝箱。

不修改数据库结构，不执行一次性数据迁移。已有活跃会话会在下一次请求时自动修复。

## 数据流

`读取会话 → 解析 transcript → 回放用户消息重建草稿 → 合并已存草稿 → 解释当前短回答 → Zod 校验 → 调用百宝箱 → 保存 transcript 与 draft`

## 测试

- 单元测试完整覆盖：大二 → 数据科学与大数据技术 → AI 产品经理。
- 验证专业短答被保存，下一缺失字段变为每周投入时间。
- 验证无效短答不会被保存为专业。
- API 回归测试验证已有 transcript 能自愈，并确认发给百宝箱的提示词包含修复后的专业。
- 运行画像相关测试、全量 `verify` 和 E2E。

## 非目标

- 本次不让百宝箱直接写数据库。
- 本次不新增长期聊天记录或数据库迁移。
- 本次不改造全部画像字段为 AI 结构化提取；后续可在 Zod 校验与降级机制下单独实施。
