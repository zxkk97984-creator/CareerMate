# CareerMate 代码审查缺陷修复设计

## 1. 目标

在现有 Next.js、Prisma、SQLite、百宝箱适配器和聊天首页上增量修复代码审查发现的问题，不重写项目，不引入外部队列或第二家 AI/搜索供应商。

完成后必须满足：

- 所有百宝箱插件入口都只能操作服务端绑定用户，调用参数不能选择其他用户。
- 聊天触发的计划生成具有真实、可查询、可失败、可重试的持久化状态，刷新页面不会丢失。
- 聊天和百宝箱插件创建的画像候选都能在对应会话中形成候选卡片。
- 联网报告不能在缺少可验证来源时标记为“实时联网调研”。
- 画像确认、职业报告提交和 Admin 入库不会在服务端失败时向用户显示成功，也不会留下半完成数据。
- 完整项目门禁和新增端到端流程通过。

## 2. 不在本次范围内

- 不引入 Redis、消息队列、独立 Worker 服务或原生小程序。
- 不修改现有百宝箱供应商，不伪造平台工具调用记录。
- 不重新设计聊天 UI，仅补充生成状态、错误和重试交互。
- 不自动删除既有计划、聊天、候选或职业报告。

## 3. 插件身份与权限

### 3.1 统一身份来源

标准 MCP 和旧 REST 兼容接口统一调用 `getPluginPrincipal(request)`。用户 ID 和权限范围只从服务端环境读取。

旧 REST 接口允许暂时保留 `userId` 参数以兼容百宝箱已有配置，但行为调整为：

- 未提供 `userId` 时使用 principal 中的用户。
- 提供的 `userId` 与 principal 不一致时返回 403。
- 每个接口检查自己的最小 scope。
- 画像候选字段继续使用同一字段白名单和事务服务，不直接写正式画像。

### 3.2 测试

为画像读取、候选创建和进度更新接口增加：绑定用户成功、跨用户拒绝、缺少 scope 拒绝、无 principal 拒绝测试。

## 4. 可靠计划生成

### 4.1 状态模型

继续使用 `CareerPlan` 作为计划和生成任务的持久化载体，不增加外部基础设施。新增状态：

- `generating`：已创建占位记录，等待执行。
- `processing`：某次生成请求正在执行。
- `pending`：结构化计划已生成，等待用户确认。
- `generation_failed`：生成失败，可重试。
- 现有 `active`、`archived` 保持不变。

`generationMeta` 保存 `triggeredBy`、`conversationId`、执行模式、失败原因、尝试次数和最近开始时间。消息中写入真实 `planId`，禁止继续写入 `__generating__`。

### 4.2 创建与去重

聊天识别到计划意图时，只执行快速数据库事务：

1. 查询同一用户已有的 `generating`、`processing` 或 `pending` 计划。
2. 有未完成计划时复用其 ID，避免重复调用百宝箱。
3. 没有时创建 `generating` 计划记录并分配版本。
4. 立即发送包含真实 ID 的 `plan_ref`。

### 4.3 执行与恢复

增加用户所有权保护的计划生成执行接口：

- 使用条件更新将 `generating` 或 `generation_failed` 原子切换到 `processing`。
- `processing` 超过约定时间可被重新接管，防止进程中断后永久卡住。
- 调用百宝箱并通过现有结构校验后，在事务中填充计划并切换为 `pending`。
- 失败时保存安全错误码和可重试状态，不删除占位记录。

聊天流通过 Next.js `after()` 尝试启动执行；前端计划卡片同时轮询状态，并在任务仍未启动、失败或超时后提供重试。这使后台执行是体验优化，而不是唯一完成路径。

### 4.4 前端

`PlanRef` 始终无条件调用 Hook，消除 Hook 顺序错误。卡片按服务端状态展示：

- 生成中：轮询并显示真实状态。
- 失败：显示安全原因和“重试”按钮。
- 待确认：显示计划摘要和“确认新版本”。
- 已生效：显示当前计划摘要。

## 5. 动态画像闭环

保留本地显式事实提取作为可靠兜底。每次百宝箱文本响应完成后，结构化卡片阶段还要查询当前用户、当前会话下新产生的 pending 候选：

- 合并本地创建候选和百宝箱插件创建候选。
- 按候选 ID 去重并生成 `profile_candidate_ref`。
- 能力字段必须关联 pending `AbilityEvidence`。
- 前端收到候选 artifact 后更新待确认数量。

旧 REST 候选兼容接口增加 `sourceConversationId`、证据摘要和影响说明，并复用标准候选创建服务。未提供会话 ID 的兼容调用仍可在成长档案查看，但不能伪装成当前消息卡片。

## 6. 来源可信度

职业探索来源 schema 调整为：

- 报告至少包含一个来源。
- `accessedAt` 必须是 `YYYY-MM-DD` 且能解析为有效日期。
- 标签为“实时联网调研”时必须提供 HTTP/HTTPS URL。
- 非 API 模式或降级模式一律移除 URL 并标记“AI分析与推断”。
- API 成功但没有合规实时来源时，不得展示“实时联网调研”。

执行元数据继续保存，但 `actualMode=api` 只证明调用了百宝箱 API，不单独作为 `search_engine` 已调用的证据。验收文档必须把平台工作流记录、搜索工具记录和应用 artifact 记录分开说明；缺少原始记录时标记为待补证据。

## 7. 事务与前端错误

### 7.1 前端

画像候选、计划确认和报告提交统一解析 API 响应。HTTP 非 2xx 或 `{ ok: false }` 时抛出错误，卡片保持原状态并展示可理解的错误信息。

### 7.2 数据库事务

- 报告提交：读取并校验报告、创建 `RoleDraft`、更新报告状态在同一事务内完成。
- Admin 通过：校验草稿后，模板 upsert、草稿状态更新、关联报告状态更新在同一事务内完成。
- 并发重复提交返回已有结果或明确 409，不产生半完成记录。

## 8. 测试和验收

先写失败测试，再实现修复。至少增加：

- 旧 REST 插件跨用户与 scope 测试。
- 计划状态机、去重、失败、重试、超时接管和真实 plan ID 测试。
- 百宝箱插件候选在当前会话生成卡片的测试。
- 实时来源无 URL、空来源、非法日期拒绝测试。
- 候选接口失败时卡片不显示成功的组件测试或 E2E。
- 报告提交和 Admin 审核的事务回滚测试。
- 从聊天请求计划、等待生成、查看计划、确认版本、刷新保留的 E2E。

最终运行：

1. `npm run secret:scan`
2. `npm run lint`
3. `npm run typecheck`
4. `npm test`
5. `npm run test:migrations`
6. `npm run build`
7. `npm run test:e2e`
8. 桌面和移动端浏览器人工检查，确认无控制台错误。

真实百宝箱验收与代码门禁分开报告。只有取得可审计的平台记录后，才把知识召回、插件调用和联网搜索标记为真实通过。

## 9. 兼容与迁移

- 保留现有 SQLite 和历史数据。
- 新状态不改变既有 active、pending、archived 语义。
- 数据迁移不得删除或重建用户业务表。
- 已持久化的 `__generating__` 历史消息由读取层显示为旧版失败占位提示，不触发不存在的计划查询；新消息不再产生该值。
- 旧 REST 百宝箱配置无需立刻删除，但必须更新为服务端绑定身份语义。
